## 2. 목표 게임 루프

### 전체 이야기

택시 도입 → 새 거처 → 샹그리아 방문 → 레베카·살아 있는 제레미와 관계 형성 → 제레미 실종 → 시신 발견·합성인간 확인 → LSPD 연락·봉쇄 → 조사 → 최종 결론 → 범인 연행 → 서장 대화·도시 야경.

제레미는 도입부 인물이자 피해자다. 발견 이후 같은 인물의 일반 조사 채팅이 열리지 않게 한다. 레베카의 사건 전후 대사·표정·행동도 단계에 따라 전환한다.

### 반복 조사

현장 탐색 → 물증/진술 획득 → 정보 DB 확인 및 진실·거짓·보류 판단 → NPC에게 정보 제시/질문 → 허용된 진술의 공개·전환 → 다른 물증/증언과 교차 검증 → 추가 탐색·재심문.

조사 중 세 결론 영역의 입증 재료를 충분히 확보하면 최종장을 해금한다. 해금 조건 충족과 정답 제출은 별개다. 재료를 확보했다고 정답을 자동 선택하거나 내부 진위를 DB에 노출하지 않는다.

### 종결

범행 수법 / 알리바이 모순 입증 / 결정적 증거의 세 빈칸에 결론과 근거를 연결한다. 게임이 세 영역의 논리와 증거 관계를 검증한 뒤 범인 특정·연행·엔딩으로 진행한다. 오답·부족한 근거의 처리 방식은 문서상 미정이며 0단계에서 결정한다. 임시 개발 검사는 유효하지 않은 제출이 성공을 발생시키지 않는 원칙을 사용한다.

조사 파트는 여러 순서로 접근 가능한 조건 그래프로 설계한다. 문서의 1~4막 작업안을 조사 순서 강제 조건으로 자동 변환하지 않는다. 시간표의 사건 발생 시각과 플레이어의 실제 조사 순서는 구분한다. 실시간 NPC 생활 시뮬레이션을 이번 요구로 추가하지 않는다.

## 4. 새로 만들거나 의미를 확장할 기능

### 4.1 공통 사건 진행과 상태

진행 단계·등장 인물·상호작용 가능 여부·공개 정보·최종장 해금·종료를 한곳에서 결정하는 작은 사건 도메인을 추가한다. 이름과 파일 분리는 구현 시 정하되 비활성 RPG나 폐기한 데모를 다시 활성화하지 않는다.

MainLoop는 현재 조작 가능 상태를 담당한다. 사건 상태는 이야기의 진척을 담당한다. SceneLoader나 개별 UI가 사건 조건과 무관하게 진행을 완료시키지 않게 한다.

### 4.2 정보와 판단의 분리

다음 정보는 서로 덮어쓰지 않도록 구분한다.

| 데이터 | 의미 |
| --- | --- |
| 객관적 사실 | 개발자가 정한 사건의 전말·시간·동선·증거 관계. NPC에게 일괄 전달하지 않음 |
| NPC 인식 | 해당 인물이 실제로 아는 내용·믿는 내용·모르는 내용 |
| NPC 발언 | 특정 단계·조건에서 공개하는 주장. 항목별 버전과 진실 일관/거짓 일관/전환 규칙 보유 |
| 획득 기록 | 플레이어가 어떤 사물·인물·진술을 통해 무엇을 얻었는지와 출처 |
| 플레이어 판단 | 진실/거짓/보류 선택과 변경 이력. 내부 정답을 수정하지 않음 |
| 입증 관계 | 어떤 정보 조합이 특정 모순이나 최종 결론을 뒷받침하는지 |

예전 진술이 새 진술로 바뀌어도 기존 발언과 당시 출처는 기록에 남긴다. 플레이어가 '거짓'을 선택했다는 이유만으로 NPC가 사실을 인정하거나 객관적 진위가 바뀌지 않는다.

### 4.3 NPC별 공개·전환·재심문

- 조사 인물마다 시간·동선·기타 정보와 공개 조건을 데이터로 작성한다. 약 5명 구성안으로 최소 15개 핵심 정보부터 검증한다.
- 단일 태도 임계값뿐 아니라 사건 단계·확보 정보·복수 첨부·기존 진술·인물별 조건을 함께 평가한다.
- 시나리오상 필요한 정보가 감정 악화만으로 영구 봉쇄되지 않도록 대체 근거·재심문 조건을 검토한다.
- 새 단서 제시로 N턴의 성실 응답 기회를 부여하고 이미 사용한 단서로 무한 재충전하지 못하게 한다. N과 새 단서의 인물별 인정 범위·회복 방식·턴 차감 시점은 0단계에서 정한다. 3턴은 제안이며 확정 기본값이 아니다.
- 이미 공개할 정보를 모두 처리한 인물의 소극적 응답과, 아직 남은 정보를 놓친 상태를 구분한다. 성실 응답은 새로운 사실·자백의 자동 해금과 다르다.

### 4.4 시나리오와 LLM 계약

흐름: 게임이 공개 가능한 진술/반응 계획 결정 → 필요한 페르소나와 허용 정보만 서버에 전달 → 답변 생성 → 현재 턴·상태 버전과 공개 계약 검증 → 성공한 정보 공개만 사건 상태에 반영.

- 모델은 말투·자연스러운 연결·질문 반응을 담당한다. 범인·사건 진위·획득 권한·진술 전환·완료 여부는 게임 규칙이 담당한다.
- 허용 정보 ID를 받는 것만으로 잘못된 자유대사까지 검증됐다고 취급하지 않는다. 필수 진술의 누락/허용하지 않은 사실 창작을 억제하는 출력 방식과 검증 실패 시 재시도 또는 작성 대사 사용을 설계한다. 단순 키워드 비교를 정답 판정기로 사용하지 않는다.
- 서버 장애·취소·늦은 응답은 정보를 추가하거나 협조 턴을 소진시키지 않게 한다. 중복 응답도 중복 획득/전환을 만들지 않는다.
- 공통 RAG와 페르소나에서 과거 피해자·공원·A-17 등 충돌 설정을 검토한다. 현재 공통 지식 파일에도 피해자를 단골로 설명하는 구형 내용이 있어 재사용 전 정리가 필요하다.
- 대소실 원인 가설은 가설로 표시하고, 시나리오의 비공개 전말 전체를 RAG에 넣지 않는다. 실제 배포에 사용할 서버 진입점과 계약 버전을 한 가지 기준으로 정리한다.

### 4.5 최종 결론과 완주

- 세 결론 영역의 입증 재료 충족 여부와 최종 UI 해금을 구현한다.
- 범행 수법·알리바이 모순·결정적 증거의 선택과 근거 연결 UI 및 검증을 새로 만든다. 별도의 보고서·점수 시스템을 필수로 추가하지 않는다.
- 기계식 문 개폐 시각만으로 인물 신원을 특정하지 않는다. 거래·혐오·정체 사전 인식만으로 유죄를 확정하지 않는다.
- 연행은 우선 연출과 LSPD 씬 전환으로 설계한다. 복잡한 동행 AI나 경로 시뮬레이션은 확정 요구가 생기기 전 필수 범위로 늘리지 않는다.
- 택시·새 거처·도입부 관계 형성·실종/발견·봉쇄·서장 대화·야경 종료를 연결한다. 택시는 도입 연출이며 별도 운전 게임을 요구하지 않는다.

### 4.6 새 게임·이어하기·저장

현재 분리된 JSON 처리 경험을 재사용하되 사건 상태를 권위 기록으로 삼는 저장 계약을 만든다. 사건/플레이 세션 ID, 진행 단계, 획득과 출처, 플레이어 판단, NPC 진술 상태·성실 응답 잔여·이미 제시한 단서, 대화, 현재 씬/위치를 함께 다룬다.

기존 NPC ID 단독 캐시와 서버 기억이 다른 사건·새 게임·저장 시점 이후의 정보를 섞지 않도록 한다. 새 게임과 불러오기 시 서버 기억 범위를 별도로 갱신하고 복원된 플레이어 기록을 기준으로 삼는다. 구형 샘플 저장은 새 사건에 자동 혼합하지 않고 격리/이전 정책을 정한다. 오류 파일은 현재 진행을 먼저 지우지 않고 거부한다.

저장 스키마와 안전한 반영 시점은 1단계에서 마련한다. 전체 씬·연출 복원은 해당 기능이 추가되는 단계마다 확장하고 6단계에서 완주 경로를 검사한다.

## 5. 개발 순서와 완료 기준

화면을 이야기 순서대로 모두 제작하기에 앞서 조사와 추리의 작동을 검증한다. 시나리오 전말 검증 → 공통 상태 → 작은 조사 루프 → 전체 사건 조사 → 세 결론 → 도입/발견 → 엔딩/재시작 → 통합 품질 순서다.

| 단계 | 작업과 산출물 | 완료 기준 | 선행 조건 |
| --- | --- | --- | --- |
| 0. 설계 정리 | 확정/임시 데이터 목록, 전말·시간표·목격 시야 검산, 정보/진술/근거 연결도, 회색 상자 수준 공간 배치안 | 최소 한 개의 유효한 해결 경로가 성립하고 근거 없는 범인 특정이 차단됨. 미정 항목의 결정 시점 명시 | 두 PDF 및 현재 기능 분석 |
| 1. 공통 사건 기반 | 단계 전환, 공통 사건 상태, 정보/진술 ID, 조건 평가, 기존 UI/저장 어댑터, 저장 버전/세션 범위와 최소 새 게임/복원 | 중복 이벤트가 중복 진행을 만들지 않고 단계·획득·진술 상태를 저장/복원. UI/로딩 입력 잠금이 충돌하지 않음 | 0의 데이터 계약. 구체적 수법 미정 동안에는 명시적 검사용 자료 사용 |
| 2. 작은 조사 루프 | 임시 공간의 사물 1개·NPC 1명·정보 공개/전환 1개, DB 판단, 새 단서 재심문, 허용 정보 기반 reply 연동 | 발견→획득→판단→제시→새 진술→기록이 실제 UI에서 반복됨. 감정과 진위가 분리되고 오류/반복 제시로 추가 해금되지 않음 | 1. 실제 사건 자료를 쓸 때는 해당 내용 확정 필요 |
| 3. 전체 수사 확장 | 약 5명 인물 구성안·최소 15개 핵심 정보, 필요한 물증·교차 증언, 여러 진술 전환, 프라이빗 홀/통로/화장실 배치, 재심문 튜토리얼 | 서로 다른 탐색·질문 순서에서도 필수 사실에 도달. 제3자 목격과 실제 시야가 맞고 인물별 공개 범위를 지킴 | 2와 실제 사건 전말·동선·전환 조건 확정 |
| 4. 최종 추리 | 세 영역의 해금, 세 빈칸 UI, 근거 연결·논리 검증·결과 설명, 정해진 오답/부족 처리 | 일부 정답이나 단독 정황증거로 성공하지 않음. 올바른 결론+근거에서만 종결 단계 전환 | 3과 최종 정답/증거 조합 확정 |
| 5. 도입·사건 발생 | 택시→거처→Bar, 레베카/제레미 대화, 실종→발견→신고·봉쇄, 사건 전후 인물/공간 전환 | 첫 실행부터 수사까지 자연스럽게 연결. 살아 있는 제레미와 관계 형성 후 발견하며 같은 사건 발생을 중복 실행하지 않음 | 1의 단계 기반과 3~4의 수사 도달점 |
| 6. 완주·저장·재시작 | 범인 반응, 연행/LSPD 전환, 서장 대화·야경, 타이틀/새 게임/이어하기, 모든 단계의 저장 복원 | 시작→수사→결론→엔딩을 완주하고 새 게임에서 이전 기억이 섞이지 않음. 불러오기 시 인물·씬·조사 기록 일치 | 4~5. 구체적 범인 반응은 작업안 확정 필요 |
| 7. 통합 검증·표현 개선 | 전체 플레이, 막힘·정답 유출·저장·장애 회귀, 목표 안내·가독성·답변 대기·동선·연출·아트 조정 | 확정된 목표 플레이 시간과 품질 기준을 충족. 서버 실패 후 회복 및 다양한 조사 순서의 완주 확인 | 0~6 |

아트·음향 자원 준비는 공간과 캐릭터 범위가 정해진 뒤 병행할 수 있다. 핵심 추리·동선 검증 이전에 최종 레벨/컷씬으로 고정하지 않는다. 실제 모델 품질 검사는 2단계부터 시작하고 이후 인물·정보가 늘 때마다 반복한다. 7단계까지 미루지 않는다.

포트폴리오의 핵심 표현 의도를 반영해 2단계의 작은 조사 루프에서 대화 맥락 유지와 TII 반응 표시까지 함께 확인한다. 7단계에서는 Tell/Affect가 어떤 반응을 뜻하는지 플레이어가 이해할 수 있는지, 표시와 실제 응답 시점이 맞는지, 정답을 과도하게 노출하지 않는지 검증한다. 새로운 별도 시스템을 만들기보다 기존 표시 기능을 우선 연결한다.

이정표는 세 가지로 묶는다.

- 1차: 1~2단계 완료 — 기존 화면을 사용해 작은 조사 흐름을 반복할 수 있음.
- 2차: 3~4단계 완료 — 사건의 조사와 세 영역 최종 입증을 플레이로 해결할 수 있음.
- 3차: 5~7단계 완료 — 새 게임부터 엔딩·이어하기까지 연결된 전체 플레이.

## 6. 단계별 검증 원칙

- 규칙은 고정 응답으로 먼저 검증하고 실제 LLM과 연결한다. 모델의 우연한 성공을 조건 평가의 성공으로 삼지 않는다.
- 새 증거가 들어올 때마다 해당 증거 없이도 잘못 통과하는 경로가 없는지 확인한다.
- E04 단독 신원 특정, E06 거래 사실만으로 유죄, E07 단독 자동 유죄처럼 원문이 경계한 단순화를 회귀 항목으로 둔다. E01~E08 자체는 확정 전까지 작업안이다.
- 진실/거짓/보류 선택 변경은 객관적 정답과 NPC 인식을 수정하지 않아야 한다. 진술 전환 전후 기록을 복원할 수 있어야 한다.
- 새 단서/기존 단서 반복, 성실 응답 잔여, 모든 정보 공개 후 소극화, 저태도 상태의 조사 지속을 검사한다.
- 응답 실패·빈 답변·취소·NPC 전환·씬 이동·새 게임·불러오기·늦은 응답에서 해금/진행을 중복하거나 이전 세션 정보를 반영하지 않는다.
- 증거 수집 순서를 바꾸거나 보류 판단을 유지해도 설계된 재조사·진행 경로가 남아 있어야 한다. 오답 처리의 정확한 행동은 0단계에서 정한 규칙을 따른다.
- 텍스트/RAG/요약에는 해당 시점의 NPC가 알 수 없는 사실과 미정 설정이 확정된 사실로 들어가지 않아야 한다.
- 합성인간을 기계 부품 노출로 설명하거나 대소실 원인을 확정하는 연출이 들어가지 않도록 세계관 검토를 포함한다.

## 7. 결정이 필요한 항목과 시점

지금은 질문에 대한 답변이나 승인을 요구하지 않는다. 다음 구현의 의존성을 계획에 표시한다.

| 항목 | 현재 상태 | 결정 시점·영향 |
| --- | --- | --- |
| 진범·동기·R-9와 감별/검증 방법 | 세부 작업안 | 0단계. 실제 사건 전말·증거·진술 확정 전 필요 |
| 5인 구성·세부 설정·레베카의 사전 인식 | 일부 확정/일부 제안 | 0단계. 인물별 공개 정보 작성 전 필요 |
| 실제 공간·출입 권한·목격 시각·E07 보존 경위 | 제안/미정 | 0단계 검산, 3단계 배치 전에 확정 |
| 새 단서의 인정 범위·N턴·차감/갱신 규칙 | 방향 확정, 수치/세부 미정 | 0단계 정책 결정, 2단계 구현 전 필요 |

| 오답·재조사·평가 방식 | 미정 | 0단계 처리 원칙, 4단계 UI 전 확정. 점수 평가 필수 가정 금지 |
| 저장 가능 시점·구형 저장 처리·종료 동작 | 이번 개발 계획에서 정할 정책 | 1단계 계약, 6단계 완주 검증 |

날짜별 일정은 위 결정과 자원 제작 범위를 확인한 뒤 산정한다. 이번 계획은 선행 의존성과 완료 기준을 제시하며 인력·아트 범위가 없는 상태에서 작업 일수를 확정하지 않는다.

## 8. 다음 작업의 구체적 시작점

다음 구현에 앞서 0단계 산출물인 **사건 전말표·NPC 정보표·증거 연결도·공간/목격 검산표**를 작성하고 제안 사항의 채택 범위를 정한다. 이후 1단계의 공통 사건 상태와 저장 계약으로 들어간다. 이번 문서 작성으로 그 구현을 시작한 것은 아니다.
