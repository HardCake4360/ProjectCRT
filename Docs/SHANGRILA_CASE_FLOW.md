# 샹그리아 첫 방문 진행

## 실행

`Assets/Scenes/Shangrila_CaseTest.unity`를 열고 Play 한다. 기존 Outdoor 및 Cutscene 테스트 씬은 별도로 유지한다.

1. 저장이 없으면 거리에서 시작한다. 목표는 샹그리아 입장이다.
2. 실제 입구 안쪽 트리거를 지나면 기존 `Shangrila_Introduction` 8턴 컷씬이 재생된다.
3. 마지막 턴 완료 또는 ESC 전체 스킵을 완료로 기록한다. 검은 화면에서 기록을 저장하고, 원래 플레이어 시점으로 돌아온 뒤 상호작용을 허용한다.
4. 레베카·제레미에게 E로 대화할 수 있다. 기존 클로즈업과 대화/조사 UI를 사용한다.
5. 실내의 영업 안내문·메뉴판을 E로 조사하면 설명이 열리고 기존 조사 인벤토리의 정보 탭에 등록된다. 두 물건은 흐름 검증용 임시 배치물이다.
6. 컷씬 완료 후 재입장하거나 Play를 다시 시작해도 같은 슬롯의 컷씬은 반복하지 않는다.

이 씬에서는 F6 컷씬 데모 실행기를 제거했다. 컷씬 반복 제작/미리보기는 기존 Cutscene 테스트 씬과 Cutscene Studio에서 진행한다.

## 저장과 불러오기

- **F5**: 걷는 상태에서 수동 저장.
- **F9**: 걷는 상태에서 저장 복원. 씬을 다시 로드하지 않고 진행·인벤토리·위치를 함께 적용한다.
- **Tab**: 기존 조사 기록 UI. 정보 탭에서 조사한 물건의 설명을 볼 수 있다.
- 컷씬 완료/스킵과 정보 등록 시 자동 저장한다. 걷는 상태에서 앱 일시중지/종료 시에도 저장한다.
- 씬 시작 시 저장을 자동으로 불러온다. 저장한 진행이 있으면 거리 시작 지점 대신 마지막 저장 위치에서 계속한다.
- 대화·조사 설명·클로즈업 이동·컷씬·일시정지 중에는 수동 저장/불러오기를 거절한다. 정상 이동 상태로 돌아온 후 사용할 수 있다.
- 취소/오류 중단은 완료로 기록하지 않는다. 입구 밖으로 나갔다가 다시 들어오면 재시도한다.

실제 슬롯: `Application.persistentDataPath/shangrila_case_v1.json`. 버전 1 JSON에 사건 식별자, 씬 경로, 완료 컷씬 ID 목록, 인벤토리의 화제/증거/정보 ID 목록, 플레이어 위치·수평/수직 시점을 기록한다. 기존 NPC 대화 기록과 다른 사건의 인벤토리 파일은 별도 시스템을 사용한다. NPC 대화 내역 전체를 이 슬롯 시점으로 되감는 기능은 이번 범위에 포함하지 않는다.

임시 파일을 디스크에 기록한 후 슬롯을 교체하며 이전 정상 파일을 `.bak`에 남긴다. 손상된 기본 파일은 백업을 읽는다. 기본 파일이 손상된 복구 상태에서는 추가 저장을 중지해 백업을 보호한다. 둘 다 읽을 수 없으면 오류 안내와 함께 거리에서 시작하되 파일을 덮어쓰지 않는다. 파일을 복구하거나 별도 보관한 뒤 다시 씬을 시작한다.

첫 방문부터 다시 시험하려면 Play를 멈추고 실제 슬롯과 `.bak`을 별도 보관한 뒤 재실행한다. 자동 검증은 별도 임시 슬롯을 사용하므로 플레이어 슬롯을 초기화하지 않는다.

## 구성과 확장

- `ShangrilaCaseManager`: 사건의 완료 기록과 두 단계(`StreetArrival` → `FreeInvestigation`), 저장·복원, 목표 안내를 담당한다.
- `ShangrilaEntranceTrigger`: 플레이어가 실제 내부 문턱에 들어왔는지 검사하고 한 번의 입장당 한 번만 시작 요청한다. 초기화 중이라면 Stay에서 재시도한다.
- `CaseInteractionGate`: NPC·물건의 `Interactable`에 붙여 사건 권한을 추가한다. 기존 `canInteract` 쿨다운과 별도로 검사하므로 대화 종료 시의 일괄 재활성화가 해금을 우회하지 않는다. 해당 컴포넌트가 없는 기존 씬은 이 사건의 영향을 받지 않는다.
- `InvestigationInventoryManager.BeginCaseSession`: 이 씬에서는 사건 슬롯 하나가 인벤토리까지 저장한다. 씬을 나가면 기존 인벤토리 설정과 데이터로 복원한다.
- 이전 저장을 불러올 때 NPC의 임시 조사 캐시도 비워 저장 후 발견한 정보가 남지 않게 한다. NPC 요청은 복원된 인벤토리에서 현재 발견 목록을 읽는다.
- `ShangrilaCaseStore`: 버전/사건/씬/좌표 검증 후 적용한다. 불러오기 실패 시 현재 플레이 상태는 바꾸지 않는다.

다음 사건 단계는 관리자의 단계/완료 조건을 확장하고 필요한 대상에 별도 권한 조건을 추가하는 방식으로 연결한다. 현재 샘플은 도착과 자유 조사 해금까지만 정의한다.

## 검증

Unity 메뉴 `Tools > ProjectCRT > Cases > Verify Arrival and Save Across Play Sessions`에서 현재 씬을 실제로 두 번 Play 하며 검증한다. 다른 Play 검증과 동시에 실행하지 않는다. 검증 중에는 스크립트를 수정하거나 씬을 전환하지 않는다.

자동 검증은 `Logs/Cases/arrival-test-<고유 ID>.json`만 쓰고 NPC 대화 저장과 서버 요청을 사용하지 않는다. 보고서는 `Logs/Cases/verification-first-session.txt`, `Logs/Cases/verification.txt`에 남긴다.

2026-10-23 Unity 6000.0.32f1에서 실제 두 번의 Play 세션 검증을 모두 통과했다. 거리 시작과 실제 이동/입장 트리거, 초기 잠금 및 쿨다운 우회 방지, 취소 후 재입장 재시도, 스킵/정상 완료의 저장, 중복 재생 방지, 기존 NPC 클로즈업/대화, 물건 조사와 정보 표시, 과거 저장으로 되돌리기, 독립 Play 세션 복원, 손상 파일 백업 복구를 확인했다. 플레이어를 내려다보는 각도에서 자기 몸을 제외하면서 상호작용용 트리거는 인식하고, 비상호작용 영역은 무시하며, 실제 벽은 판정을 막는 것도 확인했다. 독립 실행 빌드와 LLM 서버 응답 품질은 이 검증에 포함하지 않았다.
