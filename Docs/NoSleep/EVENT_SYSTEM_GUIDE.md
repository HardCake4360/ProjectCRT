# No Sleep 이벤트 시스템 제작자 가이드

작성일: 2026-10-05 (Asia/Seoul)  
범위: M1의 안정 ID·저장 이전과 M2의 공통·병렬 이벤트·디버깅

M4 이후 현재 저장은 **v4(v1/v2/v3 읽기)**다. 이 문서의 v3 설명은 M1/M2 이벤트 이전 계약이며, NPC 데이터·명령·칸 경계 예약 저장은 [M4_NPC_GUIDE.md](M4_NPC_GUIDE.md)를 함께 참고한다.

기존 이동·대사·접촉 전투·호러 여정은 그대로 사용한다. 이 문서는 새 이벤트 제작 방식과 저장 경계를 설명한다. 실제 검증 결과는 [VERIFICATION.md](VERIFICATION.md), 이후 확장은 [SYSTEM_EXPANSION_PLAN.md](SYSTEM_EXPANSION_PLAN.md)를 참고한다.

## 1. 기존 에셋을 먼저 업그레이드하기

**No Sleep > Upgrade Event Identities**를 기존 페이지 순서를 바꾸기 전에 한 번 실행한다. 기존 EventDefinition·CommonEventDefinition 에셋에 없는 ID만 발급하고 저장한다. 기존 이름·대사·라벨·조건·명령 순서·에셋 GUID는 유지한다.

| 필드 | 저장에서의 역할 |
| --- | --- |
| 맵의 mapId / 배치의 id | 원래 배치 문맥. 셀프 스위치는 맵/배치별로 유지 |
| EventDefinition.definitionId | 배치가 호출하는 이벤트 정의 |
| EventPage.pageId | 페이지 완료와 병렬 체크포인트 |
| EventPage.legacyPageIndex | 최초 변환 당시의 페이지 번호. 구버전 완료 기록의 이전표 |
| EventCommand.commandId | 명시적 체크포인트·게임 시간 대기·한 번 지급하는 트랜잭션 |
| CommonEventDefinition.commonId | 재사용할 공통 프로그램 |

최초 변환만 당시 페이지 번호를 legacyPageIndex에 기록한다. 이후 추가한 페이지는 -1이며, 페이지를 옮겨도 원래 기록을 다시 계산하지 않는다. Inspector에 저장 ID와 구버전 번호는 읽기 전용으로 표시된다.

업그레이드한 다음에는 기존 페이지를 앞뒤로 옮기거나 앞에 새 페이지를 넣어도 안정 ID가 유지된다. 업그레이드 전에 이미 순서를 변경했다면 과거 번호를 자동으로 추측하지 않는다. 원래 순서를 복구한 데이터로 이전표를 먼저 만들어야 한다.

페이지·명령을 Inspector에서 복제하면 복사된 중복 ID에 새 ID를 발급하고 경고를 표시한다. 원래 항목의 ID와 구버전 이전표는 유지한다. 에셋 파일 전체를 복제했을 때는 복제본만 선택하고 **No Sleep > Regenerate Copied Event Identities**를 실행한다. 이 작업은 복제본의 정의·페이지·명령 ID와 이전표를 새로 만들며, 대사·라벨·조건은 유지한다. 기존 저장이 참조하는 원본에 실행하면 연결이 달라진다.

**No Sleep > Validate Content**는 빈 ID, 중복 ID, 잘못된 이전표, 공통 호출 그래프·인자·배경 명령과 맵 연결을 검사한다. ID는 목록 순서나 표시 이름으로 대체하지 않는다.

### 삭제·교체와 저장 호환성

v1/v2 저장의 페이지 번호 완료 기록은 캡처한 이전표로 v3의 안정 완료 키로 이전한다. 해석할 수 없는 구버전 완료 배치·페이지, 제거된 저장 체크포인트·대기 명령, 모호한 참조는 불러오기를 취소한다. 잘못된 파일을 읽었다는 이유로 현재 세션의 진행을 새 데이터에 맞춰 초기화하지 않는다.

배포된 콘텐츠의 페이지를 삭제하거나 명령 종류를 바꾸기 전에는 기존 저장이 참조하는지 확인한다. 이전표가 필요한 페이지와 저장 가능한 Checkpoint·WaitGameMinutes의 ID를 새로 발급하지 않는다. 현재 일반적인 삭제 참조 자동 매핑 도구는 없으므로 필요한 이전 정책을 마련한 뒤 변경한다.

저장 포맷 version=3과 제작 콘텐츠 contentVersion은 별도 값이다. 구버전 읽기는 독립 후보 상태에서 이전·검증한 뒤 적용하며 원본 저장 파일을 읽기만 한다. 성공한 다음 저장에서 새 포맷을 기록한다.

## 2. 공통 이벤트 만들기

**Assets > Create > No Sleep > Common Event**에서 만든다. Inspector에서 매개변수와 명령을 정의하고, 일반 이벤트의 **CallCommon** 명령에 commonEvent와 arguments를 지정한다.

매개변수 이름은 영문 또는 밑줄로 시작하고 영문·숫자·밑줄만 사용한다. 타입은 Int, Bool, String이다. 호출에 생략한 인자는 공통 에셋의 기본값을 사용한다. 존재하지 않는 이름, 중복 인자, 타입이 다른 값은 실행 전에 거부한다.

예:

| 공통 매개변수 | 타입 | 기본값 | 호출자 A | 호출자 B |
| --- | --- | --- | --- | --- |
| visitor | String | 보관인 | 보관인 A | 보관인 B |
| number | Int | 1 | 1 | 2 |

화자에 `{param:visitor}`, 대사에 `나는 {param:number}번 보관인이야.`처럼 쓴다. 선언되지 않은 토큰은 콘텐츠 검사에서 오류가 된다. 상태 키에도 선언한 텍스트 인자를 사용할 수 있다.

SetVariable·AddVariable·AddItem·AddGold 등의 intParameter와 SetSwitch·SetSelfSwitch의 boolParameter를 지정하면 해당 지역 인자 값을 사용한다. 비워 두면 기존 intValue/boolValue를 사용한다. IfCondition의 useLocalCondition을 켜면 매개변수 이름·타입을 지정하여 지역 값을 비교한다. 정수는 기존 수치 비교, Bool·String은 일치 여부를 사용한다.

다른 공통 이벤트를 호출할 때 arguments의 fromParameter에 현재 지역 인자 이름을 지정할 수 있다. 호출마다 지역 값과 스택이 분리되며 일반 전역 변수와 혼용하지 않는다. 영구적으로 남겨야 하는 값은 GameState의 스위치·변수 등으로 기록한다.

공통 호출은 원래 배치의 셀프 스위치 문맥을 유지한다. 예를 들어 A와 B가 같은 공통 명령에서 SetSelfSwitch A를 실행해도 두 배치가 독립적으로 기록된다. End는 현재 공통 호출을 반환하고, 호출자는 다음 명령을 이어서 실행한다. 루트 페이지의 End는 그 페이지를 끝낸다.

자기 호출·상호 재귀는 금지한다. 최대 깊이는 루트 포함 16, 호출 그래프 검사 상한은 1,024회 방문이다. 실행 명령 예산은 기본 10,000개이며 자식 호출들과 공유한다. 라벨 점프와 중첩 호출로 제한을 우회하지 못한다.

## 3. 병렬 페이지 만들기

일반 EventDefinition의 페이지 trigger를 **Parallel**로 설정한다. 유효 페이지를 고르는 마지막 페이지 우선 규칙은 기존과 같다. 보이지 않는 감시 장치는 visible=false, blocksMovement=false로 설정한다.

병렬 페이지는 대사·전투·맵 이동을 직접 소유하지 않는다. 플레이어가 걷고 있는 동안 조건 확인과 허용된 상태 변경을 처리하며, 전경 이벤트·전투·UI 모달에서는 진행을 잠시 멈춘다. 페이지 조건이 바뀌거나 소속 맵이 사라지면 해당 실행을 취소한다.

| 배경에서 허용 | 용도 |
| --- | --- |
| SetSwitch, SetVariable, SetSelfSwitch | 값을 지정하는 상태 갱신 |
| IfCondition, Jump, Label, End | 조건과 제어 흐름 |
| SetObjective, RecordClue | 목표·중복을 막는 단서 기록 |
| JoinCompanion, LeaveCompanion, ClearParty, UnlockAction, ReachDestination | 동료·행동·여정 상태 |
| CallCommon | 자식까지 배경 허용 규칙을 만족하는 공통 호출 |
| GrantOnce | 한 번만 처리하는 원자적 상태 변경 |
| RequestForeground | 대사 등을 전경 큐에 요청 |
| WaitGameMinutes, Checkpoint | 루트 Parallel 페이지의 저장 가능한 대기·재개 |

배경의 직접 AddItem·AddGold·AddVariable은 허용하지 않는다. 누적 보상과 증가 연산은 GrantOnce의 mutations로 작성한다. ShowDialogue·ShowChoices·StartEncounter·TransferPlayer·실시간 Wait·AdvanceTime·UseItem·StayAwake도 배경에서 직접 실행하지 않는다. 자식 공통 이벤트 안의 금지 명령도 실행 전에 검사한다.

parallelRepeat=false는 해당 활성 페이지를 한 번 실행하고 같은 페이지가 계속 유지되는 동안 반복하지 않는다. 조건으로 페이지가 바뀌었다 돌아오면 다시 실행할 수 있다. parallelRepeat=true는 성공한 뒤 parallelIntervalSeconds의 간격으로 반복한다. 간격은 유한한 양수이며 스케줄러가 진행 가능한 실제 시간으로 계산한다. **runOnce=true**는 성공한 완료 자체를 저장하므로 다시 로드하거나 조건이 돌아와도 반복하지 않는다.

여러 배경 작업은 라운드 로빈으로 처리하며 프레임 전체 예산 128개, 작업별 한 번 처리량 16개를 사용한다. 순서나 프레임 속도에 의존하는 보상은 작성하지 않는다. 반복 감시에는 종료·대기 조건과 충분한 간격을 둔다.

## 4. 중복 보상을 막는 GrantOnce

GrantOnce의 mutations에 함께 변경할 내용을 작성한다. 지원 효과는 SetSwitch, SetVariable, SetSelfSwitch, AddVariable, AddItem, AddGold다.

예를 들어 아이템 한 개를 지급하면서 획득 스위치도 켜려면 같은 mutations 목록에 두 효과를 넣는다. 잘못된 키·종류·오버플로 등으로 검증이 실패하면 변경과 트랜잭션 기록 전체를 적용하지 않는다. 성공했으면 두 상태와 지급 기록이 한 번에 확정된다.

트랜잭션은 원래 맵/배치·정의·페이지, 공통 호출 경로와 명령 ID로 구분한다. 같은 명령을 반복하거나 저장 후 다시 실행해도 중복 지급하지 않는다. 다른 배치가 같은 공통 이벤트를 호출하면 서로 독립적으로 받을 수 있다.

지급 기록은 저장에 포함한다. 같은 보상을 다른 새 명령으로 옮기거나 복사본 ID를 발급하면 새 트랜잭션이 되므로 기존 지급과 동일한 것으로 취급하지 않는다.

## 5. 저장 가능한 게임 시간 대기와 체크포인트

루트 Parallel 페이지에 다음처럼 작성한다.

1. GrantOnce: 표식 지급과 수량 기록.
2. WaitGameMinutes: 게임 시간 십 분 대기.
3. Checkpoint: 이후 흐름을 재개할 지점.
4. RequestForeground: 표시등 알림 요청.

WaitGameMinutes는 게임 내 elapsedMinutes에 기한을 더해 기록한다. 실시간 십 분을 기다린다는 뜻이 아니다. 제작 시간 모드에서는 다른 사건의 AdvanceTime으로 게임 시간을 보내야 한다. 읽기나 보통 이동만으로 시계가 진행하지 않는 설정에서는 계속 대기한다.

대기 중 저장한 후 로드하면 같은 명령 ID와 기존 dueElapsedMinutes를 재사용한다. 다시 십 분을 추가하지 않는다. Checkpoint는 저장한 명령의 **다음 명령**부터 재개한다. 해당 명령이나 루트 페이지가 없어졌거나 지원하지 않는 명령으로 교체되었다면 불러오기를 거부한다. 저장 기록에 명령 종류 자체는 없으므로 같은 ID의 WaitGameMinutes와 Checkpoint를 서로 바꾼 경우까지 자동 감지하지는 않는다. 배포한 재개 명령의 종류를 유지한다.

맵 이탈·조건 탈락·명시적 취소는 런타임 실행을 버리지만 저장된 명시적 재개 지점을 유지한다. 같은 페이지가 다시 유효해지면 거기서 시작한다. 성공적으로 페이지를 끝내면 재개 기록을 지운다. 새 게임은 기존 진행과 재개 지점을 초기화한다.

현재 WaitGameMinutes·Checkpoint는 **루트 Parallel 페이지에서만** 사용할 수 있다. 전경 페이지나 공통 호출 내부의 지속 체크포인트·게임 시간 대기는 지원하지 않는다. 호출 스택·지역 변수·Coroutine을 직렬화하지 않기 때문이다. 체크포인트가 없는 배경 프로그램은 다시 처음부터 시작하므로 누적 효과에는 GrantOnce를 사용한다.

## 6. 전경 요청과 저장 경계

RequestForeground에 foregroundEvent를 지정한다. 요청 대상은 Parallel이 아닌 유효 페이지여야 한다. 필요하면 전경에서 공통 이벤트를 호출하여 대사·선택·전투를 처리한다.

요청은 FIFO 큐에서 한 번에 하나씩 처리한다. 같은 원래 배치·대상 정의·페이지의 중복 예약은 합친다. 큐 상한은 32개다. 실행 직전에 세션 세대, 요청 원래 배치의 활성 상태·페이지, 대상 페이지 조건과 완료 여부를 다시 확인한다. 맵 전환·새 게임·로드·취소로 유효성을 잃은 예약은 실행하지 않는다.

큐 자체는 런타임 데이터이며 저장하지 않는다. **전경 예약이 남아 있으면 저장을 차단하므로 예약된 알림을 처리한 뒤 저장한다.** 대사·선택·전투·상태 갱신 한가운데도 저장하지 않는다. 반면 병렬 프로그램이 WaitGameMinutes에서 기다리는 안전한 경계에는 이동과 수동 저장이 가능하다. 디버거에서 저장 차단 이유를 확인할 수 있다.

전경 요청은 현재 맵의 원래 배치에 속한다. 맵을 떠나면 그 맵의 대기 예약은 취소된다. 반드시 확인해야 하는 이야기라면 알림을 마친 후 이동하도록 제작한다.

로드는 원본 파일·현재 상태를 보존한 후보에서 이전과 참조 검증을 마친 뒤 런타임 작업을 교체한다. 실패한 로드는 이전 세션과 맵으로 복구한다. 배경 작업은 복원된 지속 상태에서 다시 만들어진다.

## 7. 실행 디버거

Play 상태에서 **No Sleep > Event Debugger**를 연다. 필요하면 게임 세션을 선택한다.

- 전경과 병렬 작업의 배치·페이지·프로그램·명령 ID 및 실행 수.
- 공통 호출 스택, 현재 대기 이유, 최근 명령 기록과 오류.
- 전경 요청 큐와 실행 소유권·입력 차단·저장 차단 이유.
- 현재 맵 배치의 활성 페이지·조건 판정과 전역 스위치·정수 변수·배치 셀프 스위치 검색 조회. 표시 행 수를 제한하며 상태를 변경하지 않는다.
- 최근 완료·실패·취소한 병렬 실행. 스케줄러가 최대 16개를 보관하며 각 실행 기록은 최대 256줄이다. 전경 영역에는 현재 또는 마지막 전경 실행을 표시한다.

**일시 정지**는 전경·병렬 명령과 게임의 실시간 시계를 멈춘다. **명령 한 단계**는 현재 명령을 한 단계 진행한다. 공통 호출 명령과 자식의 첫 명령은 별도 단계다. 대사나 선택은 화면에서 마쳐야 하며, 게임 시간 대기는 기한을 만족해야 한다. Step 버튼이 시간 비용을 임의로 지불하거나 선택을 자동으로 확정하지 않는다.

**전경 취소**는 현재 전경 실행을 중단한다. **전체 취소**는 전경·병렬·예약을 정리하고 디버거 정지를 해제한다. 이미 확정된 보상이나 스위치를 되돌리는 버튼은 아니다. 명시적인 배경 재개 지점은 유지하므로 조건이 계속 유효하면 스케줄러가 다시 실행을 만들 수 있다. 디버깅을 끝내면 **실행 재개**로 정상 진행을 복구한다.

에셋 버튼으로 원래 이벤트를 찾을 수 있다. 실행 코드는 시작 때 명령을 복사하므로 플레이 도중 원본 에셋 수정으로 현재 호출 스택을 교체하지 않는다.

현재 호출별 지역 매개변수의 값은 조회 API에 노출하지 않는다. 타입·이름은 공통 에셋과 호출 Inspector에서 확인하며 실행 위치·호출 경로는 디버거에서 확인한다.

## 8. 별도 시스템 샘플 사용하기

**No Sleep > Create Systems Lab**을 실행하거나 `Assets/NoSleep/Scenes/NoSleepSystemsLab.unity`를 연다. 생성 메뉴는 기존 씬과 사용자가 편집한 데이터를 덮어쓰지 않는다. 데이터는 `Assets/NoSleep/Data/SystemsLab`에 두며 기존 데모·호러 여정과 분리한다. 새 씬은 기존 빌드 목록에 추가된다.

1. Play를 누르고 새 게임을 시작한다. WASD/방향키로 이동하고 E/Enter/Space로 대화한다.
2. 보관인 A와 B를 각각 만나 표식을 받는다. 같은 공통 프로그램이 이름·번호 인자를 다르게 받고 두 배치의 셀프 스위치를 독립적으로 기록한다.
3. 뒤쪽 장치에서 **장치를 켠다**를 선택한다. 두 병렬 페이지가 원자적으로 각 표식을 지급하고 게임 시간 십 분을 기다린다.
4. 장치 대사가 끝난 후 F5 또는 상태창의 슬롯에서 저장한다. 대기 중인 체크포인트와 지급 기록을 확인한다.
5. 장치의 **십 분을 보낸다**를 선택한다. 두 전경 알림을 차례로 닫은 뒤 저장할 수 있다.
6. 이전 대기 저장을 불러와 다시 시간을 보낸다. 표식과 횟수가 중복 지급되지 않고 원래 기한에서 알림으로 진행되는지 확인한다.
7. 장치의 **옆 보관실로 간다**와 돌아오는 문으로 맵 이탈·재개를 확인한다. 기다리는 동안 옆방 시계로 시간을 보낼 수도 있다.
8. Event Debugger를 열어 정지·단계 실행·취소, 호출 스택과 저장 차단 이유를 확인한다.

이 씬은 제작 기능 확인용이다. 피로 누적을 0으로 둔 별도 설정을 사용하며 본편 생존 밸런스나 세계관을 결정하지 않는다. 자동 검증은 실제 실행한 결과만 VERIFICATION과 진행 이력에 기록한다.

## 9. 현재 범위

M1/M2는 안정 ID와 이전, 타입이 있는 공통 호출, 제한된 병렬 실행, 원자적 지급·루트 체크포인트, 전경 큐·디버거를 제공한다. 전용 명령 재정렬·복사/템플릿과 참조·맵 편집은 M3에서 제공하며 [제작 가이드](M3_AUTHORING_GUIDE.md)를 참고한다. NPC 이동/일과, 전환·음향·카메라 명령과 전경/공통 호출의 중간 저장은 이후 단계다.

Coroutine·실행 스택·입력 잠금·UI 객체·예약 큐를 파일에 저장하지 않는다. 명시한 지속 상태와 게임 시간 기한을 검증해서 다시 실행한다. 새로운 본편 설정·수면 실패 규칙·동료의 운명·결말을 이 시스템 샘플로 확정하지 않는다.
