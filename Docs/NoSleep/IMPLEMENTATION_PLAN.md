# Project No Sleep 구현 계획

작성일: 2026-10-04 (Asia/Seoul)  
실제 Unity 프로젝트: `C:\Users\user\Documents\GitHub\projectNoSleep`  
기준 환경: Unity 6000.0.32f1 / URP 17.0.3 / Input System 1.11.2

## 프로젝트 방향

3D 어드벤처 게임을 제작한다. RPG 메이커의 데이터 기반 제작 흐름을 Unity에서 제공하는 것이 시스템 개발의 목표다. 초기 시점은 쿼터뷰이며, 카메라와 이동 로직을 분리하여 추후 자유 시점으로 교체할 수 있게 한다. 게임 고유의 스토리, 모델, 연출보다 맵 제작, NPC, 대사, 이벤트 실행 기반을 우선한다.

## 최초 조사 결과 (2026-10-04, 구현 전)

최초 조사 당시 프로젝트는 URP 기본 템플릿 단계였다. `SampleScene`과 기본 입력 에셋, URP 설정이 있었으며 게임 전용 코드는 없었다. 기존 씬, 렌더 파이프라인, 패키지 설정을 보존하고 게임 코드를 `Assets/NoSleep`에 추가했다. 최초 조사에서 Git 저장소가 아님을 확인했으며 임의로 저장소를 초기화하지 않는다. 현재 구현 상태는 아래 진행 상태와 진행 이력에 기록한다.

## 구현 원칙

- 제작 데이터는 ScriptableObject 에셋으로 저장하고 실행 상태는 별도 직렬화 모델로 유지한다.
- 맵은 XZ 평면의 정수 격자를 기준으로 한다. 타일은 3D 프리팹 또는 기본 큐브로 렌더링하며 이동 가능 여부를 데이터로 관리한다.
- NPC와 오브젝트는 공통 이벤트 정의를 사용한다. 뒤쪽 페이지부터 조건을 검사하여 유효한 페이지를 선택한다.
- 스위치, 정수 변수, 이벤트별 셀프 스위치, 소지품 및 플레이어 상태는 공통 게임 상태에서 관리한다.
- 입력, 카메라, 이벤트 실행, 대사 표시, 저장을 분리한다. 대사와 이벤트 실행 중 플레이어 입력을 잠근다.
- 제작 도구에는 Undo, 데이터 유효성 검사, 안전한 저장을 제공한다.
- 구현 중 진행 이력을 `Docs/PROJECT_HISTORY.md`에 계속 추가한다. 완료·검증·미완료를 구분하고 검증되지 않은 기능을 완료로 기록하지 않는다.

## 1차 구현 범위: 시스템 기반과 플레이 가능한 샘플

1. **공통 상태와 저장**: 전역 스위치/변수, 셀프 스위치, 플레이어 이름·체력·정신력·소지금, 아이템 수량, 슬롯 저장/불러오기. 저장에는 현재 맵, 플레이어 위치 및 방향을 포함하고 포맷 버전을 검증한다.
2. **3D 타일맵**: 맵 크기·타일 크기·시작 지점, 지면/장식 레이어, 타일 팔레트, 이동 제한, 맵 에셋 편집 창, 브러시/지우개/채우기, 씬 미리보기, 이벤트 배치.
3. **플레이어**: WASD/방향키 이동, 달리기, 충돌 및 이동 가능 타일 검사, 쿼터뷰 추적 카메라, 가까운 NPC/오브젝트 상호작용, 상태창.
4. **대사**: 화자, 문장, 타이핑 효과, 다음 문장, 선택지와 선택 결과, 이벤트 실행과 연동.
5. **이벤트**: 조건별 페이지, 버튼 상호작용/플레이어 접촉/자동 실행 트리거, 일회성 실행, 대사, 선택지, 스위치/변수/셀프 스위치 변경, 아이템·소지금 변경, 조건 분기, 대기, 맵 이동. 무한 루프 방어 및 중복 실행 차단.
6. **NPC와 제작 흐름**: NPC 이름·프리팹·이벤트 정의, 맵 좌표 배치, 시각적 표시와 상호작용 프롬프트. 이동 경로 및 일과는 후속 단계에서 추가한다.
7. **검증용 콘텐츠**: 샘플 맵과 다른 맵으로 통하는 문, 조건에 따라 대사가 바뀌는 NPC, 셀프 스위치를 쓰는 아이템 오브젝트, 접촉 이벤트. 메뉴에서 샘플을 생성하고 Play로 확인할 수 있게 한다.
8. **개발 문서와 테스트**: 제작자 가이드, 조작법, 데이터 구조, 상태/조건/저장/맵 테스트, Unity 컴파일과 테스트 결과 기록.

### 1차 완료 기준

- 기존 URP 설정을 유지한 상태로 Unity에서 오류 없이 컴파일된다.
- 샘플을 생성하여 플레이어 이동·상호작용·대사·선택지·페이지 전환·맵 이동·상태창을 연결한다.
- 맵 편집 창에서 타일과 이벤트 데이터를 수정하고 저장할 수 있다.
- 저장 후 게임 상태, 현재 맵과 플레이어 위치를 복원한다.
- 자동 검증 결과와 실제 플레이 검증 여부를 이력에 명시한다.

## 2026-10-05 추가 시스템 계획

상세 계획은 [SYSTEM_EXPANSION_PLAN.md](SYSTEM_EXPANSION_PLAN.md)에 정리했다. 기존 구현을 기준선으로 유지하고 다음 순서로 확장한다.

1. M1: 안정적인 이벤트/페이지/체크포인트 ID, v1/v2 이전, 실행 소유권과 안전 저장 경계.
2. M2: 공통 이벤트, 제한된 병렬 실행, 전경 요청 조정과 실행 디버깅.
3. M3: 전용 이벤트 편집기, 복사/재정렬/템플릿, 맵 팔레트·지역·연결 편집.
4. M4: NPC 이동·일과, 충돌/점유 조정, 보이는 적의 순찰/접근과 상태 복원.
5. M5: 안전한 맵 전환, 카메라·음향·화면·대사 연출.
6. M6: 아이템/목표 카탈로그, 짧은 구간에서 시간·전투·수면 규칙 검증.
7. M7: 사용자 설정/입력 변경, 별도 자동 저장, 접근성·성능·독립 실행 빌드 검증.

계획 수립 이후 첫 구현 묶음 M1/M2를 진행했다. 저장 v3/v1·v2 호환, 이벤트/페이지/명령 ID 이전, 실행 문맥과 안전 저장 경계, 공통 이벤트와 타입 인자, 제한된 병렬 실행·중복 없는 원자적 지급·체크포인트, 전경 요청 큐와 디버거를 연결했다. `NoSleepSystemsLab.unity`를 별도 샘플로 추가했으며 기존 제작 에셋의 페이지 번호는 최초 ID 업그레이드 시 보존한다.

사용법은 [EVENT_SYSTEM_GUIDE.md](EVENT_SYSTEM_GUIDE.md), 최종 검증과 실제 적용은 `VERIFICATION.md`/`PROJECT_HISTORY.md`에 기록한다. M3 제작 도구는 [세부 계획](M3_AUTHORING_PLAN.md)에 따라 구현했다. 전용 이벤트 편집/템플릿·상태 키/참조 조회·맵 사각 편집과 지역/시각 변형·복제·연결 검사의 사용법은 [M3 제작 가이드](M3_AUTHORING_GUIDE.md)에 기록한다.

M4는 [세부 계획](M4_NPC_PLAN.md)에 따라 NPC/경로/일과 데이터, 결정적 제한 탐색·동적 예약, 전경 명령·순찰/접근, 안전한 칸 경계 예약 저장과 v4(v1~v3 읽기)를 연결했다. 제작·샘플 사용법은 [M4 NPC 가이드](M4_NPC_GUIDE.md)에 기록한다. 다음은 M5의 맵 전환·카메라·음향·화면 연출이며 M6/M7과 정식 콘텐츠는 후속 범위다. 미정 시간/전투/수면 규칙은 현재 프로토타입 기준을 유지한다.
