# No Sleep 구현 검증 기록

날짜: 2026-10-04 (Asia/Seoul)

## 환경과 방식

- Unity 6000.0.32f1 / URP 17.0.3 / Input System 1.11.2 / Test Framework 1.4.5.
- 기존 프로젝트의 설정과 동일한 패키지 버전을 사용하는 별도 Unity 검증 복사본에서 실행했다. 패키지는 실제 프로젝트의 로컬 PackageCache를 참조했다.
- 실제 프로젝트에는 신규 `Assets/NoSleep`와 문서, 샘플 씬의 빌드 목록 항목을 전달한다. 기존 SampleScene, 입력 에셋, URP 설정과 패키지 구성은 보존한다.
- Unity 밖의 C# 컴파일 검사에 더해 Unity가 직접 에셋을 임포트하고 런타임/에디터/테스트 어셈블리를 컴파일했다.

## 자동 검증

- 샘플 에셋과 `NoSleepDemo.unity` 생성 성공, Unity 종료 코드 0.
- `No Sleep > Validate Content`: 샘플 맵과 이벤트 명령 검사 통과.
- EditMode: 57개 통과, 실패/건너뜀 0개.
- PlayMode: 12개 통과, 실패/건너뜀 0개. 실제 키보드 입력으로 이동하고 벽 앞에서 멈추는 검사도 포함한다.
- 합계: 69개 통과. 보고서에서 모든 테스트가 실행되었으며 건너뛴 테스트는 없다.

EditMode는 상태 키, 조건 비교, 수량 범위, 셀프 스위치 분리, 저장 직렬화·백업·잘못된 포맷, 맵 크기 변경, 팔레트 재배열, 격자 변환·이동 가능 여부·프리팹 충돌, 페이지 우선순위와 이벤트 명령 검사를 포함한다.

PlayMode는 실제 부트스트랩과 플레이어/UI/카메라 초기화, 이벤트 실행 중 맵 이동과 이전 지형 정리, 이동 불가 목적지 복구, 상태 스냅샷, 대사·선택·분기, 일회성 완료 상태, 취소·예외·무한 반복 시 잠금 해제, 입력 잠금 중 접촉 이벤트 예약과 재진입을 검사한다. 사용자 저장 파일에 쓰지 않으며 저장 파일 테스트는 별도 임시 디렉터리를 사용한다.

## 검증 중 수정한 문제

- TestAssemblies 자동 참조와 중복된 명시적 TestRunner 참조를 제거했다.
- 이동 차단형 접촉 이벤트의 트리거를 격자 경계 밖까지 확장하여 접근 시 실행되게 했다.
- 다른 이벤트가 실행 중일 때 접촉한 이벤트가 누락되지 않게 대기 후 한 번 실행하도록 했다.
- Unity JSON이 누락된 객체를 기본 생성하는 동작을 고려하여 저장의 필수 루트 필드와 객체 형식을 먼저 검사하고, 누락된 숫자 데이터는 유효하지 않은 기본값으로 검사한다.
- 유효한 시작 지점이 없는 맵으로 전환할 때 현재 맵과 플레이어 위치를 복원한다.
- 숨겨진 배치 실행에서 테스트 키보드가 Game 뷰 포커스 때문에 비활성화되지 않게 테스트 입력 환경을 설정하고 종료 시 원래 설정으로 복원한다. 실제 게임의 입력 설정은 변경하지 않는다.

## 남은 검증과 제한

자동 PlayMode 검증과 사람이 실제 게임 화면을 보고 플레이하는 검증은 구분한다. 스토리의 재미, 한국어 폰트의 플랫폼별 표시, 게임패드 실기기, 실제 배포 빌드, 큰 맵 성능과 아트/연출은 아직 검증하지 않았다. 현재 샘플은 기본 도형을 사용한 시스템 확인용 콘텐츠다.

원본 테스트 보고서는 `Docs/Validation/EditMode.xml`, `Docs/Validation/PlayMode.xml`에 보관한다.

## 2026-10-05 — M3 제작 도구

- MapVisual PlayMode 2개: 큐브/프리팹 양 레이어 회전·높이, 충돌 bounds와 이동 좌표 Y=0, 영역 태그의 이동 불변, 복제 모델 콜라이더 비활성화와 원본 프리팹/리짓바디 보존.
