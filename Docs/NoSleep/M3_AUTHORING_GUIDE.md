# No Sleep M3 제작 도구 가이드

작성일: 2026-10-05 (Asia/Seoul)  
대상: Unity의 Assets/NoSleep 제작 에셋

이벤트 목록 편집, 재사용 조합, 상태 키 조회, 사각형 맵 편집과 연결 검사 사용법이다. 저장 ID·공통/병렬 실행 규칙은 [EVENT_SYSTEM_GUIDE.md](EVENT_SYSTEM_GUIDE.md), 기본 조작은 [CREATOR_GUIDE.md](CREATOR_GUIDE.md)를 참고한다. 실제 실행한 검증 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

## 1. 이벤트 편집 창

**No Sleep > Event Editor**를 연다. 상단에서 일반 EventDefinition 또는 CommonEventDefinition을 선택하거나 **새 이벤트**, **새 공통**을 만든다. 왼쪽은 페이지, 가운데는 명령 목록, 오른쪽은 선택한 페이지·명령 설정이다. 공통 이벤트는 페이지 없이 하나의 프로그램과 지역 인자를 편집한다.

- 페이지 **추가**, **복제**, **위로/아래로**, **삭제**를 사용한다. 뒤쪽 페이지 우선 판정은 유지된다.
- 명령 종류를 선택하고 **추가**하면 선택 명령 다음, 선택이 없으면 목록 끝에 넣는다.
- **검색**으로 명령 종류·문장·키·목적지를 찾는다. 클릭은 단일 선택, Shift는 범위, Ctrl은 추가 선택이다.
- **전체 선택**, **분기 범위**, **선택 해제**로 복사할 범위를 고른다.
- **위로/아래로**는 선택 명령들을 상대 순서를 유지한 하나의 묶음으로 옮긴다.
- **복사**, **복제**, **붙여넣기**, **삭제**를 사용하고 Ctrl+Z 또는 Unity의 Undo/Redo로 되돌린다.
- **저장**은 제작 에셋을 저장한다. 실행 상태의 저장 슬롯과 별개다.

Play 중 제작 데이터 편집을 잠그며 실행 상태는 **No Sleep > Event Debugger**에서 확인한다. 검사는 에셋·페이지·명령 위치를 표시하고 해당 진단을 누르면 그 위치를 선택한다. 코드나 일반 Inspector로도 데이터를 편집할 수 있으므로 제작을 마친 뒤 **No Sleep > Validate Content**를 실행한다.

### 분기 묶음과 외부 라벨

IfCondition은 조건이 거짓이면 targetLabel로 이동하고, 참이면 다음 명령을 실행한다. ShowChoices의 각 항목은 해당 라벨로 이동한다. 라벨은 현재 페이지 또는 공통 프로그램 안에서만 유효하다.

**분기 범위**는 선택한 명령이 사용하는 라벨과 그 범위의 명령을 포함하도록 선택을 넓힌다. 선택 결과를 확인하고 복사한다. 내부 Label·Jump·IfCondition·선택지 연결은 함께 복사되며 붙여넣는 프로그램에 같은 라벨이 있으면 복사본 라벨과 그 내부 참조를 함께 바꾼다.

기본적으로 복사 범위 밖 라벨을 참조하는 블록은 붙여넣기/복제를 거부한다. 기존 목적지 프로그램의 라벨을 의도적으로 재사용할 때만 **같은 프로그램의 범위 밖 라벨 연결 유지**를 켠다. 이 옵션도 목적지에 실제 있는 라벨만 허용한다. 다른 프로그램의 라벨을 호출하는 기능은 아니다.

삭제로 다른 명령의 분기 대상이 사라지거나 라벨이 중복되는 작업은 적용 전에 거부한다. 비어 있는 대사·미연결 맵처럼 아직 제작 중인 의미 오류는 데이터를 작성할 수 있게 두고 검사에서 보고한다.

클립보드는 No Sleep 명령 블록 JSON과 저장된 에셋 참조를 사용한다. 에디터 재시작 뒤에도 남아 있는 클립보드와 같은 프로젝트의 에셋을 다시 해석한다. 참조한 에셋이 없어졌거나 다른 타입이면 붙여넣기를 취소한다. 임시 객체를 참조한 블록은 에셋을 먼저 저장해야 한다.

### ID와 기존 저장

최초 **Upgrade Event Identities**를 페이지 재정렬 전에 실행한다. 이동·재정렬은 기존 페이지/명령 ID와 legacyPageIndex를 유지한다. 복제·붙여넣기·템플릿 적용은 복사본에 새 ID를 발급하고 새 페이지의 legacyPageIndex를 -1로 둔다.

새 ID를 받은 보상 명령은 원래 보상과 다른 거래다. 이미 배포한 보상을 복제하면 기존 저장에서 새 보상으로 처리될 수 있다. 페이지 삭제, 저장 가능한 WaitGameMinutes/Checkpoint 삭제·교체는 기존 저장의 참조에 영향을 주므로 원본을 보존하고 이전 정책을 확인한다.

## 2. 템플릿으로 제작하기

왼쪽 **템플릿 추가**를 펼친다. 기본 조합과 필요한 화자·대사·참조를 지정하거나 저장한 EventTemplateDefinition을 선택한다. 일반 이벤트는 **새 페이지로 추가**, 공통 이벤트는 **공통 종료 앞에 조합 추가**를 사용한다. 기존 페이지나 에셋 전체를 덮어쓰지 않는다.

| 조합 | 설정할 내용 |
| --- | --- |
| NpcDialogue | 화자와 문장 |
| OneTimeReward | 아이템 ID/수량, 소지금, 획득 문장 |
| ConditionalBranch | 조건 종류/키/수치, 목적지 맵과 칸 |
| StayAwake | NightActivityDefinition, 완료 문장 |
| ContactCombat | EnemyDefinition |
| CommonCall | CommonEventDefinition, 생성된 타입 인자의 실제 값 |

공통 이벤트에는 단일 페이지 템플릿의 명령만 적용한다. 기존 마지막 End 앞에 삽입하며 조합의 마지막 End는 제외해 연속 조합이 실행되도록 한다. 페이지의 trigger·runOnce·conditions는 공통 프로그램에 적용되지 않는다. 앞부분에 있는 기존 End/Jump 등 조기 반환 경로는 제작자가 확인한다.

일반 이벤트의 일회 보상은 GrantOnce로 지급을 보호하고 대사까지 끝내면 runOnce 페이지를 완료한다. 접촉 전투는 PlayerTouch·비차단 페이지에서 시작하고 승리했을 때만 격파/완료를 기록한다. 밤샘의 동료/시간 조건 실패는 후속 대사와 완료를 진행하지 않는다.

**No Sleep > Create Authoring Templates**는 기존 호러/Systems Lab 에셋을 연결한 여섯 예제를 `Assets/NoSleep/Data/Authoring/Templates`에 만든다. 같은 폴더의 StateKeys.asset은 상태 키 선언 예제다. 재실행은 기존 템플릿·선언 내용을 보존한다. 원본 예제의 목적지/밤샘/적/공통 에셋이 필요하다.

**기본 조합을 에셋으로 저장**하면 같은 조합을 다시 사용할 수 있다. 저장한 템플릿은 제작용 에셋이다. 적용 뒤 각 이벤트는 새 ID를 가진 별도 데이터이며 이후 템플릿 변경을 자동 반영하지 않는다. 배경에서 금지한 대사·맵 이동·전투가 있는 조합은 Parallel에 그대로 적용할 수 없다.

## 3. 키와 콘텐츠 사용 위치

**No Sleep > Content Browser**를 연다.

- **카탈로그**: 현재 제작 에셋에서 읽거나 쓰는 스위치/변수/아이템 ID, 아이템 효과의 ID, 동료 정의와 공통 이벤트를 모은다. 키의 **사용 위치**를 누르면 같은 키의 위치를 조회한다.
- **사용 위치**: 검색과 종류 필터로 에셋·페이지·명령을 찾는다. 위치를 누르면 Event Editor 또는 Map Editor로 이동한다.
- **진단**: 누락된 에셋/맵/라벨 참조와 오타 가능성을 구분한다.
- **선언 목록**: StateKeyRegistry를 만들고 switchKeys, variableKeys, itemIds를 등록한다. 수정은 Undo로 되돌리고 **에셋 저장**으로 보존한다.

선언 에셋은 Assets/NoSleep 아래에 저장한다. 실제 사용 중인 키도 자동으로 목록에 포함하므로 기존 이벤트의 자유 키를 모두 등록해야 실행할 수 있는 구조는 아니다. 읽기 키가 선언·쓰기 사용처·관련 정의에 없으면 오타 가능성 **경고**를 표시한다. 이 경고만으로 이벤트 실행이나 저장을 막지 않는다. {param:key}처럼 호출 인자에서 결정되는 키는 고정 전역 키로 등록하지 않는다.

Event Editor의 **참조 갱신** 또는 세부 설정의 **기존 상태 키/에셋 목록 불러오기**를 사용하면 스위치·변수·아이템·동료 키와 공통 에셋을 목록에서 선택할 수 있다. 직접 입력도 가능하다. 목록은 스냅샷이므로 새 에셋이나 다른 창의 변경 뒤 새로 고침한다.

사용 위치·진단은 한 번에 최대 250행, 키 목록은 종류별 최대 250개를 표시한다. 검색을 좁혀 나머지 위치를 조회한다. 이 창의 선언은 제작 데이터이며 런타임 스위치 값이나 기존 저장 파일을 바꾸지 않는다.

## 4. 사각형 맵 제작

**No Sleep > Map Editor**를 연다. 기존 맵을 선택하거나 **새 맵**, **맵 복제**를 사용한다.

팔레트에서 이름/프리팹을 검색하고 썸네일로 타일을 선택한다. 지면/장식 레이어를 구분한다. 브러시/지우개는 한 칸씩 칠하며 **Select** 또는 Shift+드래그는 사각형을 고른다.

- **선택 칠하기/지우기**는 선택 영역의 현재 레이어를 바꾼다.
- **영역 복사**, **선택 칸에 붙여넣기** 또는 Ctrl+C/V는 양 레이어·영역 ID·시각 변형을 함께 복사한다.
- 이벤트 포함 옵션을 켜면 선택 영역의 배치도 함께 복사한다. 복사본 배치 ID를 새로 발급하여 셀프 스위치를 공유하지 않는다.
- **레이어 채우기/비우기**는 맵 전체에 적용한다.
- 시작점은 이동 가능한 지면에 놓고 **맵 검사**로 확인한다.

### 배치와 맵 복제

이벤트 배치에서 정의를 선택하고 **사각형 전체 배치**로 여러 칸에 놓거나 선택 칸에 하나를 추가한다. 사각형 안의 배치를 한꺼번에 선택하고 복제 이동량을 지정해 복제한다. 복사/붙여넣기와 선택 삭제도 지원한다.

**맵 복제**는 새 mapId와 배치 ID를 발급한다. 타일/지역/시각 데이터는 복사하며 EventDefinition 참조와 기존 이동 명령의 목적지 참조는 유지한다. 복제한 맵의 문을 새 맵으로 연결하려면 해당 이벤트의 이동 목적지를 따로 편집한다. 원본과 같은 이벤트 정의를 편집하면 두 맵에 함께 영향을 준다.

맵 ID와 배치 ID를 직접 바꾸면 저장의 셀프 스위치 연결이 달라진다. 표시 이름 변경과 구분한다.

### 지역 ID와 시각 변형

**Region** 도구 또는 **선택 영역 ID**로 0 이상의 정수 지역 ID를 칠한다. 0은 미지정이다. 지역 표시와 충돌 표시를 켜면 맵 그리드와 씬 미리보기에서 비교한다. 지역 ID는 후속 NPC/연출이 사용할 제작 태그이며 현재 태그만으로 새 게임 규칙을 실행하지 않는다.

셀별 회전은 90도 단위, 시각적 높이는 유한한 숫자로 지정한다. 브러시와 **선택 시각 변형**으로 적용한다. 회전/높이는 **Visual 모델**에만 적용하며 CellToWorld·이동 평면·충돌은 기존 XZ 격자를 유지한다. 높이를 올렸다고 계단·다층 이동이 생기지 않는다.

씬 미리보기는 창이 만든 임시 오브젝트만 생성·제거한다. 실제 씬의 사용자 오브젝트를 대체하지 않는다. 제작 에셋은 **에셋 저장**으로 보존한다.

## 5. 맵 연결 창

**No Sleep > Map Connections**를 연다. 그래프 노드를 누르면 해당 맵을 연다. 연결 목록의 **명령 위치**, **출발 배치**, **목적지 칸**은 해당 편집 위치로 이동한다.

분석 대상은 Assets/NoSleep의 모든 MapDefinition 에셋이다. 각 배치의 페이지에서 직접 TransferPlayer, 중첩 CallCommon, RequestForeground가 호출하는 이벤트를 따라가며 연결을 모은다. 대상 맵 누락/분석 목록 밖 참조, 범위 밖·이동 불가 목적지와 잘못된 시작점은 **오류**다.

여러 페이지·조건·분기·선택지·전경 요청을 거친 연결은 **조건부 경고**로 표시한다. 돌아오는 연결이 없으면 경고하며, 의도된 단방향 이동은 제작 정책으로 표시할 수 있다. 조건부 연결이나 반환 연결의 존재만으로 실제 퀘스트 도달 가능성을 증명하지 않는다. 씬 Bootstrap의 maps 목록도 실제 실행에 맞게 따로 연결한다.

### 단방향과 필수 연결 선언

Content Browser에서 만든 StateKeyRegistry를 연결 창의 **선언 에셋**에 지정한다. 출발/목적지와 다음 플래그를 선택하고 **이 방향의 정책 저장**을 누른다.

| 플래그 | 검사 |
| --- | --- |
| 의도된 단방향 / allowOneWay | 해당 방향에 대한 반환 연결 없음 경고를 해제 |
| 필수 연결 / requireConnection | 해당 출발→목적지 이동이 하나도 작성되지 않으면 오류 |

연결 행의 **단방향 의도 표시**는 그 방향을 표시하며 기존 필수 정책을 지우지 않는다. 단방향 표시도 잘못된 목적지나 조건부 경고를 숨기지 않는다. 정책을 해제하거나 제거하려면 선언 에셋의 mapLinks를 편집한다.

그래프는 최대 60개 노드와 300개 선을 표시하며 연결·진단 목록은 검색당 250행이다. 호출 재귀/깊이와 분석량 상한은 무한 분석을 막는 경고다. 큰 구조에서는 해당 경고를 해결한 뒤 누락된 연결을 다시 검사한다.

## 6. 제작 후 확인 순서

1. 새 에셋을 저장하고 Event Editor·Content Browser·Map Connections를 새로 고침한다.
2. 분기 블록과 페이지를 옮긴 뒤 검사하고, 복사한 보상·배치가 원본 ID를 공유하지 않는지 확인한다.
3. Undo/Redo로 에셋 변경을 되돌린 뒤 재저장하고 다시 열어 데이터가 유지되는지 확인한다.
4. **No Sleep > Validate Content**의 실제 오류를 해결하고 조건부/미선언 키 경고의 의도를 확인한다.

6. 일회 진행 후 저장/불러오기와 맵 전환을 확인한다. M3 제작 편의 기능 때문에 저장 포맷 버전을 올리지 않는다.
