# 무수면 호러 RPG 구현 계획

작성일: 2026-10-04 (Asia/Seoul)  
기준: `무수면_호러_RPG_요구사항.md`, 기존 1차 시스템 구현, 저장·불러오기를 고려하라는 사용자 추가 지시.

## 해석과 범위

첨부 문서는 게임 설계 자료다. 확정된 방향, 사용자가 제시한 아이디어, 미정 항목 및 AI 참고 예시를 구분한다. 참고 예시를 확정 세계관으로 채택하지 않는다. 재앙의 원인, 괴물의 실체, 동료의 생사와 결말을 임의로 결정하지 않는다.

기존 Unity 6000.0.32f1 / URP 17.0.3과 제작 시스템을 확장한다. 먼저 저장 슬롯과 호환성·복원 흐름을 보강한 뒤, 아래 게임 시스템과 연결된 플레이 가능 프로토타입을 구현한다. 수치·전투 방식·시간 방식과 샘플 대사는 검증을 위한 임시 설계이며 정식 기획 확정으로 간주하지 않는다.

| 저장·불러오기 | 슬롯 선택, 메타 정보, 이어하기, 백업 읽기, v1 저장 마이그레이션 | 모든 실행 상태 + 위치/방향/맵 |

## 구현 순서와 완료 기준

### A. 저장·불러오기 확장

- 슬롯 목록(기본 6개), 맵·날짜·시간·목표·저장 시각 요약, 빈/손상 파일 표시.
- 타이틀 새 게임/이어하기와 플레이 중 슬롯 저장/불러오기, 덮어쓰기 확인 및 백업 읽기.
- 저장 포맷 v2. 기존 v1은 새 시스템의 기본 상태를 채워 읽는다. 미래 버전은 거부한다.
- 피로·시간·각성, 동료, 단서·일지·목표, 배운 행동, 이벤트 완료, 인벤토리와 능력치를 같은 스냅샷으로 저장한다.
- 저장/로드는 이벤트·대사·전투가 끝난 안전한 경계에서 수행한다. 잘못된 맵 또는 위치·파일로 로드하면 현재 세션을 유지한다.
- 테스트는 사용자 저장 폴더 대신 전용 임시 경로를 사용한다. 세션의 실제 저장→변경→로드→모든 상태 복원을 PlayMode에서 검증한다.

### B. 생존·여정·성장 기반

- `SurvivalSettings` 에셋에 임시 밸런스와 시간 방식 설정을 둔다. 기본은 제작자가 지정한 이동·작업·전투 시간 비용이며, 일반 대사 읽기는 시간을 소비하지 않는다. 실시간 모드는 선택적으로 지원하고 모든 모달 UI에서 멈춘다.
- 기본 피로는 시간에 따라 증가한다. 일시적 각성은 유효 피로를 낮추며 만료 시 원래 피로 압박이 돌아온다. 내성·수면 부채 등 별도 수치는 도입하지 않는다.
- 피로 최대치만으로 즉시 자동 사망시키지 않는다. 실패/수면 판정은 미정이므로 초기에는 상태 경고와 이동/전투 불리함을 주되 진행 가능한 하한을 유지한다. 체력 0 전투 패배는 로드/새 게임 화면으로 이어진다.
- 몸과 적의 기초 수치는 날짜에 따라 함께 낮아진다. 최소치를 두고, 해금한 행동과 동료 보조로 선택 가짓수를 늘린다.
- 단서와 동료 ID를 안정적으로 저장한다. 추억은 동료 이탈 후에도 남기며 밤새기 이벤트를 불행으로 뒤집지 않는다.

### C. 접촉 전투 프로토타입

- 전투 방식은 미정이므로 대사·선택 UI를 재사용하는 교체 가능한 턴 선택 방식으로 검증한다.
- 공격·방어·이탈, 해금 가능한 과격한 공격과 관찰 행동, 각성제 사용을 제공한다.
- 과격한 행동은 체력 대가와 일시적 각성 효과를 가진다. 이 수치는 허구의 게임 밸런스다.
- 전투 중 입력/저장/시간을 제어하고 승리·이탈·패배 결과를 분리한다. 승리만 배치별 셀프 스위치에 기록하여 재방문·로드 후 적이 부활하지 않게 한다.
- 이탈 직후 같은 접촉으로 무한 재전투하지 않게 기존 접촉 재진입 규칙을 사용한다.

### D. 제작 도구와 샘플 여정

- 이벤트 명령에 시간 진행, 단서 기록, 목표 설정, 동료 영입/이탈, 행동 해금, 밤새기, 전투 시작, 아이템 사용을 추가한다. 기존 enum 값은 유지한다.
- 조건에 날짜·피로·동료·단서·행동 해금을 추가하고 Inspector와 콘텐츠 검사에서 필요한 데이터 오류를 표시한다.
- `NoSleepHorrorPrototype` 씬과 아파트→병원→중간 거점→목적지 접근 맵을 새로 생성한다. 이전 데모 에셋은 보존한다.
- 뉴스 도입, 각성제, 두 NPC의 서로 다른 단서, 동료, 긍정적인 밤새기, 접촉 전투와 회피 경로, 행동 해금, 후반 동료 이탈을 샘플 데이터로 연결한다.
- 샘플 목적지와 대사는 시스템 검증용이다. 최종 원인·결말을 확정하지 않고 목적지 도달까지 연결한다. 정식 14일 분량의 완성 콘텐츠는 별도 제작 단계다.

## 코드와 데이터

- `Runtime/Survival`: 설정, 저장 가능한 생존/여정/동료 상태, 시간·각성·성장 규칙.
- `Runtime/Combat`: 적 정의, 전투 규칙 및 선택 UI를 사용하는 실행기.
- `Runtime/Core`: 세션 통합, v2 저장·마이그레이션, 슬롯 메타 정보.
- `Runtime/UI`: 타이틀·슬롯·상태·일지, 피로/시간 HUD, 아이템 사용.
- `Runtime/Events`: 신규 명령·조건 및 배치별 전투 완료 연동.
- `Editor/HorrorPrototypeBuilder`: 신규 설정/적/밤새기 활동/맵/이벤트/씬 생성과 검사.

## 검증과 문서

- EditMode: v1/v2·손상/백업·메타 정보, 낮/밤 경계·각성 만료·낮밤을 걸친 시간 비용, 쇠약 하한·적 약화, 영입/이탈·추억 보존·단서 중복·행동 해금.
- PlayMode: 실제 슬롯 저장/복원·불리한 목적지 롤백, 전투 결과·비용·중복 접촉 방지·취소 잠금 해제, UI 초기화, 새 씬 생성/콘텐츠 검사.
- 원본 테스트 보고서와 적용 결과를 진행 이력에 기록하고 제작자 가이드에 조작·데이터 작성·저장 정책을 추가한다.

## 미정 항목의 후속 결정

정식 시간 모델, 수면/실패 판정, 전투 진행 방식, 각성제 대가와 피로 곡선, 여정 기간·레벨 규모, 주인공/동료 설정, 재앙과 목적지의 정체, 결말은 플레이 테스트와 사용자 결정을 통해 확정한다. 그래픽·애니메이션·오디오와 1~2주 전체 콘텐츠는 이 시스템 검증 이후 제작한다.

## 구현 결과

계획의 A~D를 구현했다. 신규 호러 씬에서 제목 화면부터 중간 저장·복귀, 14일째 목적지 도달까지 연결한다. 날짜는 이벤트 비용으로 압축하여 진행하며 14일 분량의 정식 맵과 이야기를 완성한 것은 아니다. 기본 도형과 대사로 제작 기능을 검증하고, 원인/결말·동료의 행방은 남겨 둔다. 검증 수치와 실제 프로젝트 적용은 `VERIFICATION.md`와 `PROJECT_HISTORY.md`에 기록한다.
