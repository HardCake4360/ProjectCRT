## 1. 목표와 현재 기준선

다음 목표는 **맵·NPC·사건·연출을 데이터로 제작하고, 제작한 긴 여정을 저장·복원할 수 있는 게임 제작 환경**이다. 기존 동작을 보존하면서 반복 제작과 검증에 필요한 기능부터 확장한다.

계획 수립 당시 기준선은 기본 맵 편집, 플레이어·쿼터뷰·상호작용, 대사/선택/조건별 이벤트, 전역·셀프 스위치, v2 저장/6개 슬롯/백업/v1 호환, 시간·피로·각성·쇠약, 단서·목표·동료·추억, 접촉 전투와 4개 맵의 샘플 여정이었다. 당시 검증은 EditMode 135개와 PlayMode 31개 통과였다. 이후 M1/M2 구현 결과와 최신 검증은 문서 마지막 및 `VERIFICATION.md`에 기록한다.

계획 수립 당시 단일 이벤트 실행기와 페이지 번호에 연결된 완료 기록을 우선 해결 대상으로 삼았다. M1/M2에서 실행 문맥·스케줄러·안정 ID와 이전 규칙을 추가했다. 정적인 NPC 배치, 평면 격자, 단일 목표 중심 여정과 제한적인 연출/설정은 후속 범위로 남는다.

## 3. M1 — 저장·콘텐츠 ID·실행 상태 기반

### 구현할 기능

- 기존 맵 ID와 이벤트 배치 ID를 유지하고, 이벤트 정의/페이지 및 새로 저장되는 NPC·목표 단계에 안정적인 ID를 둔다. 표시 이름·파일명·목록 순서와 저장 키를 분리한다.
- 페이지 복제 시 새로운 페이지 ID를 발급하고 재정렬 시 ID를 유지한다. 명령 enum의 기존 숫자도 보존한다.
- 저장 체크포인트와 일회성 보상 단위에는 안정적인 명령/트랜잭션 ID를 둔다. 호출한 공통 이벤트와 배치 페이지의 완료 키도 구분한다.
- 현재 `__nosleep_completed_page_<번호>` 완료 기록을 안정적인 페이지 ID로 이전한다. 당시 페이지 구성에 대응하는 변환표를 보존하고, 페이지를 재정렬한 뒤 현재 번호만 보고 과거 완료를 추측하지 않는다.
- 저장 포맷 버전과 제작 콘텐츠 판본을 구분한다. 영구 저장 필드가 추가될 때 다음 포맷을 도입하고 v1/v2에서 순차적으로 이전한다. 문서나 에디터 편의 기능 추가만으로 버전을 올리지 않는다.
- 입력, 대사/선택, 전투, 맵 전환, 이벤트 실행을 관리하는 공통 실행 상태를 정리한다. 어느 작업이 입력·UI·시계를 소유하는지 명시하며 취소/예외 때도 해제한다.
- 실행별 문맥에 원래 배치 키·호출 경로·맵/세션 세대·취소 상태를 둔다. 기존 `session.Events` 진입점을 유지하면서 실행 스택을 분리하고, 새 게임/로드 뒤 이전 작업이 새 상태를 변경하지 못하게 한다.
- 저장 요청이 스냅샷을 만들 수 있는 안전한 경계에 도달했는지 판정한다. 상태를 변경하는 작업이 반쯤 끝난 순간에는 기록하지 않는다.

### 완료 기준

v1/v2 원본 JSON을 새 포맷으로 읽은 후 아이템·단서·추억·행동·격파·일회성 보상이 유지된다. 완료한 이벤트의 페이지를 앞에 삽입하거나 재정렬해도 다시 보상하지 않는다. 변환 불가능한 참조는 명확한 오류와 함께 현재 세션을 유지한다. 기존 166개 회귀 검사와 신규 이전 검사가 통과한다.

## 4. M2 — 공통·병렬 이벤트와 디버깅

### 공통 이벤트

`CommonEventDefinition`과 호출 명령을 추가한다. 공통 이벤트는 같은 명령 해석기를 사용하며 호출한 배치의 셀프 스위치 문맥을 기본으로 상속한다. 전역 공통 이벤트의 지속 상태는 별도 공통 이벤트 ID로 구분한다. 인자는 타입과 이름을 명시하고 호출자 변수와 임시 지역 변수를 구분한다.

중첩 호출의 반환·종료 범위와 실패 전달을 정의한다. 자기 호출/상호 재귀, 지나치게 깊은 호출과 무한 점프를 검사하며 실행 중 오류에는 호출 경로를 표시한다. 대사나 전투를 시작하는 공통 이벤트는 전경 이벤트 안에서 실행한다.

### 병렬 이벤트

기존 단일 `EventRunner`를 단순히 여러 개 복제하기보다 전경 실행과 병렬 작업을 조정하는 실행 관리자(`EventScheduler`, 명칭은 구현 시 조정)를 추가한다.

- 대사·선택·전투·맵 전환은 한 전경 작업만 소유한다. 병렬 작업은 직접 UI를 빼앗지 않고 전경 실행을 요청한다.
- 1차 병렬 명령은 조건 검사, 제한된 상태 변경, 명시적인 대기와 전경 이벤트 예약으로 한정한다. 이동·연출 명령은 해당 서비스가 준비되는 후속 단계에서 허용한다.
- 지속 상태 변경은 반복해도 같은 결과인 갱신 또는 효과와 지급 완료 기록을 한 번에 커밋하는 일회성 트랜잭션으로 제한한다. 예를 들어 `소지금 지급 → 대기 → 완료 표시` 사이의 저장 후 처음부터 재실행하는 방식은 중복 보상을 만들므로 허용하지 않는다. 임의의 다단계 지급 스크립트는 우선 전경 작업으로 실행한다.
- 병렬 작업의 프레임당 실행량·동시 수·호출 깊이에 제한을 둔다. 실행 순서를 안정적으로 정하고 상충하는 상태 변경을 조정한다.
- 조건이 참인 동안 매 프레임 새 작업을 만드는 대신 조건 진입 시 실행, 종료 후 재무장 또는 명시한 반복 간격을 선택한다. 자동 실행 이벤트의 UI/전투 중 대기 정책도 정의한다.
- 요청을 중복 제거하고 실제 시작 전에 조건·페이지·접촉·맵 생존 여부를 다시 검사한다. 상태 변경 알림 안에서 새 작업을 즉시 재진입시키지 않는다. 페이지가 바뀌면 그 페이지에 속한 병렬 작업을 정리한다.
- 게임 시간 대기와 실제 연출 초 단위 대기를 구분한다. 모달·전경 이벤트 중 시계와 NPC 정지 정책을 일관되게 적용한다.
- 맵에 속한 작업은 맵 해제 시 취소한다. 전역 작업은 공통 서비스 범위에서만 유지하고 해제된 오브젝트를 참조하지 않는다. 새 게임·로드·씬 종료·예외 시 예약과 잠금까지 정리한다.
- 맵 이동을 시작한 전경 이벤트는 세션 문맥에서 후속 명령을 계속할 수 있게 하되 원래 셀프 스위치 키를 유지한다. 이전 맵 오브젝트를 사용하는 명령은 다시 조회하거나 실패를 반환한다.
- 병렬 작업이 존재한다는 이유만으로 저장을 영구 차단하지 않는다. 안전한 경계에서 잠시 정지하고 지속 상태만 저장한다. Coroutine과 명령 실행 스택을 파일에 저장하지 않는다.
- 로드 후 기본 병렬 작업은 맵 준비가 끝난 시점에 조건을 다시 검사하고 페이지 시작에서 재생성한다. 재개가 필요한 작업만 선언된 재개 진입점의 안정적인 체크포인트 ID와 게임 시간 기한, 필요한 지속 변수로 복원한다. 이미 커밋한 트랜잭션은 다시 실행되어도 효과/보상을 지급하지 않는다. 임의의 중첩 호출 스택을 재구성하는 방식은 첫 범위에 포함하지 않는다.

### 디버깅

개발자 창에 실행 중인 맵/배치/페이지 ID, 명령 위치, 호출 스택, 조건 결과, 예약된 작업과 잠금 이유를 표시한다. 일시정지·한 명령 진행·중단, 스위치/변수 조회와 제한된 실행 기록을 지원한다. 개발자 기능은 일반 플레이 화면과 배포 빌드에서 분리한다.

### 완료 기준

두 NPC가 같은 공통 대사를 호출해도 셀프 스위치가 섞이지 않는다. 병렬 알림과 시계 조건이 돌아가는 동안 플레이어는 움직이고 수동 저장도 가능하다. 대사 요청 두 개는 정해진 순서로 한 번씩 표시된다. 반복 조건·재귀·맵 전환·취소로 무한 실행이나 숨겨진 UI 잠금이 발생하지 않는다. 병렬 상태 변경 중 요청된 저장을 불러와도 중복 보상과 부분 갱신이 없다.

## 5. M3 — 이벤트·맵 제작 도구 확장

### 이벤트 제작

전용 `Event Editor` 창을 만든다. 첫 버전은 목록/들여쓰기 기반으로 제작하며 기존 직렬화 명령과 라벨을 유지한다. 그래프 편집기는 제작에 필요한 정도를 확인한 뒤 판단한다.

- 명령 추가/검색/이동/복사/붙여넣기/중복, 페이지 복제/재정렬과 Undo/Redo.
- 조건 분기·선택지·공통 이벤트를 묶어서 편집하고, 내부 라벨을 함께 옮겨 잘못된 점프가 생기지 않도록 처리.
- NPC 대화, 아이템 획득, 잠긴 문, 밤샘 활동, 접촉 전투 등 기존 명령 조합을 재사용하는 템플릿.
- 스위치/변수 등록 목록과 기존 공통 이벤트·동료 정의에서 선택하고 사용 위치·깨진 참조를 조회. 아이템은 현재 데이터의 ID 목록 선택부터 지원하고 M6에서 전체 아이템 카탈로그를 연결.
- 오류에서 해당 에셋·페이지·명령으로 이동. 에셋 수정과 실제 플레이 중 상태 변경을 구분.

### 맵 제작

팔레트 검색·프리팹 썸네일, 사각형 선택/칠하기/복사, 이벤트 다중 선택·복제·배치, 지역 ID 칠하기, 표시/충돌 확인을 추가한다. 타일의 셀별 회전과 시각적 높이 오프셋을 편집하되, 실제 이동 가능한 다층 지형은 별도 설계로 분리한다.

맵 연결 창은 이동 명령/출입구에서 연결을 수집한다. 잘못된 목적지·시작점·필수 연결 누락을 보고하며, 의도된 단방향 연결과 조건부 연결을 구분한다. 정적인 연결 그래프만으로 모든 퀘스트 조건이나 실제 도달 가능성을 증명했다고 표시하지 않는다.

### 완료 기준

코드 작성 없이 새 NPC, 한 번 받는 아이템, 조건부 문, 공통 이벤트와 밤샘 장소를 제작한다. 선택지 묶음을 복사하고 페이지를 재정렬해도 분기와 저장 상태가 유지된다. Undo/Redo 및 에디터 재시작 후 데이터가 보존된다. 맵 복제 시 새 맵/배치 ID를 발급하고 기존 맵의 상태를 공유하지 않는다.

## 6. M4 — NPC 이동·일과와 보이는 적 행동

### 이동과 일과

`NpcDefinition`, 이동 경로 데이터와 런타임 이동 서비스를 추가한다. 우선 같은 맵 안에서 정지/바라보기/정해진 경로/반복 순찰/목적지 이동을 지원한다. 타일 이동 가능 여부와 실제 NPC·플레이어 점유를 함께 사용하며 격자 경로 탐색, 이동 칸 예약, 길막힘 시 재탐색·제한된 대기·실패 반환을 제공한다.

현재 맵 충돌 검사에서 움직이는 NPC 자신을 제외할 수 있게 하고, 경로 탐색 결과와 이동 직전 점유 검사를 연결한다. 자신이 서 있는 칸 때문에 경로를 막거나 이미 다른 액터가 예약한 칸으로 이동하지 않게 한다.

대화·전투·일반 모달에서는 배경 NPC 이동을 정지한다. 전경 연출이 명시적으로 요청한 이동은 같은 이동 서비스에서 실행하고 완료/실패를 반환한다. NPC 두 명이 같은 칸을 향하거나 좁은 통로에서 만났을 때 무한 대기·겹침이 생기지 않도록 조정한다.

일과는 저장된 게임 날짜/시각과 스토리 조건을 기준으로 선택한다. 장거리 이동으로 시간이 크게 뛸 때 분마다 전체 경로를 재생하지 않고 현재 일과의 유효한 위치로 재평가한다. 스토리상 영구 위치 변경은 일과보다 우선하며 저장한다. 맵 간 NPC 이동은 1차 맵 내부 이동이 안정화된 뒤 별도 확장한다.

### 보이는 적

같은 이동 기반으로 정지/순찰/제한된 감지·접근을 지원한다. 감지 거리·시야·추적 종료 조건은 적 데이터로 조정한다. 맵에 보이는 적과의 접촉만 전투를 요청하며 랜덤 인카운트를 추가하지 않는다. 승리 후의 배치 격파 상태와 이탈 후 재진입 규칙을 유지한다.

### 저장과 완료 기준

영구 위치·방향·이동/일과 체크포인트를 안정적인 NPC/배치 ID로 기록한다. 실제 탐색 경로와 보간은 재생성하며 이동 중 저장 요청은 유효한 칸 경계까지 대기한다. 동료 추적의 시각적 위치는 계속 재생성한다.

NPC 이동 중 저장 후 복원, 길막힘/두 NPC 교차, 대화 중 정지, 시간 점프 후 일과, 맵 이동/로드/취소를 검증한다. 이동하는 적에 접촉해도 전투는 한 번만 시작되고 승리 후 로드해도 부활하지 않는다. 복원된 NPC가 출입구/플레이어를 막으면 정해진 안전 위치 정책을 적용하거나 로드를 완전히 취소한다.

## 7. M5 — 안전한 전환과 연출

목적지 사전 검사 → 페이드 아웃 → 목적지 준비/최종 검증 → 맵·NPC·플레이어 적용 → 카메라 정렬 → 페이드 인의 전환 흐름을 제공한다. 목적지 실패나 취소 때 이전 맵·NPC·플레이어와 화면 밝기·입력·음향을 복구한다. 전환 중에는 저장을 보류한다.

쿼터뷰를 유지하며 목표 추적·특정 위치 보기·이동/확대·기본 시점 복귀를 명령으로 지원한다. 자유 시점은 필요 여부와 조작을 결정한 뒤 별도 확장한다. 전경 연출의 카메라 제어와 일반 플레이 추적이 동시에 동작하지 않도록 소유권을 관리한다.

음향은 BGM, 반복 환경음, 효과음 채널을 분리하고 맵/지역 설정, 페이드·크로스페이드·중지와 볼륨 조절을 제공한다. 낮밤 조명, 지역별 분위기, 제한된 화면/색 효과, 그림·초상·대사 로그·읽기 속도 조절을 순서대로 연결한다. 필수 연출을 줄여도 목적과 진행 정보를 알 수 있게 한다.

낮밤과 피로는 시각·음향 강도에 연결할 수 있지만 괴물의 실체나 세계 법칙을 새로 확정하지 않는다. 좋은 밤샘 이벤트의 추억과 경험을 불행으로 뒤집는 연출은 추가하지 않는다. 오브젝트 이동·문/장치 반응은 기존 상태와 연출 명령을 연결하고, 추가 퍼즐 규칙은 실제 콘텐츠가 필요할 때 만든다.

### 완료 기준

코드 없이 NPC 이동·대사·카메라·효과음·맵 전환을 순서대로 연출한다. 실패/스킵/취소 후 검은 화면이나 입력 잠금이 남지 않고 맵별 음악이 겹치지 않는다. 연출 종료 후 정상 저장·복귀가 가능하며 화면 효과를 낮춘 설정에서도 진행할 수 있다.

## 8. M6 — 아이템·목표 데이터와 게임 규칙 검증

### 아이템과 목표

아이템 ID별 이름·설명·아이콘·분류·사용 조건·효과를 `ItemDefinition` 카탈로그로 제공한다. 기존 소지품 ID와 수량은 유지하며 각성제를 첫 데이터로 연결한다. 중요한 진행 아이템을 실수로 버리거나 비용만 지불하고 효과가 실패하지 않도록 소비/효과를 함께 검증한다. 장비·제작·상점·교환은 필요가 정해졌을 때 추가한다.

`ObjectiveDefinition`에 목표/단계/조건/후속 목표와 필요한 기록을 둔다. 현재 단일 목표를 호환되게 이전하고, 보상 완료 상태를 별도로 기록하여 재로드나 조건 재평가로 재지급하지 않는다. 메인 목표와 선택 기록을 구분하고 기존 단서·추억을 연결한다. 퀘스트 UI의 표시 범위는 플레이어가 실제로 얻은 정보로 제한한다.

### 시간·전투·수면 규칙 검증

10~20분 정도의 짧은 검증 구간을 먼저 제작해 이동/작업/읽기/전투/밤샘의 시간 비용, 피로 상승·각성 만료, 동료 이탈 전후와 적 약화를 비교한다. 목표 플레이 시간은 제작 후 실측해 조정한다. 시간 소비가 큰 선택에는 실행 전 예상 시간과 비용을 보여 주고, 진행에 필요한 자원이 없어지는 경로를 확인한다.

기존 제작 시간/실시간 모드와 전투 결과 계약을 유지하면서 선택한 규칙을 교체할 수 있도록 조정한다. 최종 시간 방식·수면 판정·실패 조건·전투 방식이 결정되기 전에는 현재 경고/하한과 체력 0 실패를 기준으로 검증한다. 피로가 높다는 이유로 새 자동 사망을 임의로 추가하지 않는다.

### 완료 기준

기존 저장의 각성제·목표·단서·추억이 새 카탈로그/UI에서 유지된다. 소모 실패와 보상 재평가에 손실/중복이 없다. 동료 없이도 마지막 구간을 통과할 수 있고 필요한 이동/밤샘이 자원 고갈로 막히지 않는다. 같은 구간을 복원했을 때 비용과 지속 상태가 일관된다. 규칙 확정은 아래 결정 사항과 플레이 결과를 기록한 뒤 진행한다.

## 9. M7 — 설정·자동 저장·배포 준비

음량·화면 모드/해상도·대사 속도·자막/글자 크기·화면 흔들림/효과 감소를 제공한다. 이동·상호작용·메뉴 입력은 재지정 가능한 입력 정의로 정리하며 충돌 안내·기본값 복원·게임패드 프롬프트를 지원한다. 사용자 설정은 진행 저장과 별도 파일로 관리하고 새 게임/다른 슬롯 로드 후에도 유지한다.

자동 저장은 성공한 맵 이동·주요 목표/밤샘 완료 뒤 안전한 경계에 예약한다. 수동 6개 슬롯과 분리하고 쓰기 실패·손상·백업 복구가 수동 저장에 영향을 주지 않게 한다. 자동 저장 방식과 빈도는 플레이 검증 후 조정한다.

배포 폰트 에셋과 필요한 라이선스를 정리하고, 에디터에서만 되는 코드가 플레이어 빌드에 섞이지 않는지 검사한다. 현재 개발 환경을 기준으로 Windows 플레이어 검증부터 시작하고 실제 지원 플랫폼을 정한 뒤 확대한다. 큰 맵/NPC 수를 측정하여 병렬 명령 예산, 맵 생성·충돌·UI·음향의 비용을 확인하고 필요한 부분에만 청크/풀링을 적용한다.

### 완료 기준

설정과 유효한 바인딩이 재실행/새 게임/다른 저장 후 유지된다. 게임패드와 키보드로 필수 UI 전체를 조작할 수 있다. 독립 실행 빌드에서 새 게임 → 사건·이동·밤샘·전투 → 저장 → 종료 → 재실행 → 이어하기를 완료한다. 자동 저장 실패는 현재 진행과 수동 파일을 보존한다. 성능 기준은 측정 기기·목표 해상도·맵 규모와 함께 기록한다.

## 12. 첫 구현 묶음과 다음 작업

첫 구현은 **M1 기반과 M2의 공통 이벤트·병렬 실행 최소 기능·실행 상태 조회**를 한 묶음으로 진행했다. 다음 여섯 항목의 코드·샘플·검증을 연결했다.

1. 현재 이벤트·페이지·저장 키/호출·잠금 상태를 조사하고 v1/v2 원본 회귀 자료를 고정한다.
2. 페이지 ID와 이전표, 전경/병렬 소유권·안전 저장 경계 계약을 구현한다.
3. 호출 문맥을 유지하는 공통 이벤트와 제한된 병렬 작업/전경 요청 큐를 구현한다.
4. 기존 Inspector에 필요한 새 필드를 연결하고 실행 위치·잠금/대기 이유를 조회하는 개발자 창을 추가한다.
5. 기존 데모와 호러 에셋을 덮어쓰지 않는 별도 시스템 샘플에서 공통 대사·조건 감시·동시 요청·맵 이동/취소·저장 복원을 검증한다.
6. 이전 166개 회귀 검사와 신규 의미 있는 검사를 실행하고 실제 프로젝트에 반영한 뒤 이력·가이드·검증 기록을 갱신한다.

이번 결과는 저장 v3(v1/v2 호환), 최초 순서를 캡처한 ID 이전, 공통 인자와 호출자 상태, 프레임 예산을 가진 병렬 실행, `GrantOnce` 원자적 지급, 루트 병렬 페이지의 체크포인트/게임 시간 기한, 전경 요청 큐와 개발자 디버거다. 사용법과 정책은 [EVENT_SYSTEM_GUIDE.md](EVENT_SYSTEM_GUIDE.md), 실행 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

Coroutine·중첩 호출 스택·요청 큐는 저장하지 않는다. 기본 병렬 페이지는 조건을 재검사해 시작하며 명시적 루트 체크포인트만 재개한다. 전경 요청이 남아 있으면 메뉴를 닫고 예약된 연출을 처리한 뒤 저장한다. 공통 내부의 지속 대기와 임의 위치에서 실행 스택 복원은 이번 범위에 포함하지 않는다.
