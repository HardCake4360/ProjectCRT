# No Sleep M4 NPC 제작 가이드

작성일: 2026-10-05 (Asia/Seoul)  
대상: 같은 맵 안에서 움직이는 NPC, 일과와 보이는 적

이 단계는 기존 이벤트·맵·저장에 선택적 NPC 프로필을 연결한다. 기본 맵 제작은 [M3_AUTHORING_GUIDE.md](M3_AUTHORING_GUIDE.md), 공통/병렬 실행과 저장 경계는 [EVENT_SYSTEM_GUIDE.md](EVENT_SYSTEM_GUIDE.md)를 참고한다. 실제 검증 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

## 1. NPC와 경로 만들기

**Assets > Create > No Sleep > NPC > Definition**으로 NpcDefinition을 만든다. **NPC > Route**로 NpcRouteDefinition을 만들고 경유지 목록을 편집한다.

| 제작 데이터 | 역할 |
| --- | --- |
| npcId | NPC 정의의 안정 ID |
| displayName, prefab, fallbackColor | 이름과 시각 모델 |
| speed, blocksMovement | 초당 격자 칸 이동 속도와 점유 |
| route | 기본 경로. 비우면 기본적으로 정지 |
| schedules | 날짜·시각·상태 조건에 따른 경로 또는 정지점 |
| enemy와 감지 설정 | 보이는 적의 순찰·플레이어 접근 |
| routeId, points, repeat | 경로 ID, 경유지와 반복 여부 |
| 경유지 cell, yaw, waitSeconds | 목적지 칸, 도착 방향과 실시간 대기 초 |

NPC·경로·일과 ID는 Inspector에서 읽기 전용이다. 누락 ID는 제작 변경 단계에서 Undo와 함께 발급하며 콘텐츠 검사나 Play 조회는 발급하지 않는다. Inspector 목록에서 일과를 복제하면 복사본에 새 scheduleId를 주고 원래 항목을 유지한다.

에셋 전체를 복제했으면 복제본의 Inspector에서 **복제한 에셋의 ID 새로 발급**을 사용한다. 표시 이름과 경로 참조는 유지한다. 원본 저장이 참조하는 정의에 실행하면 다른 정의가 되므로 복제본을 선택했는지 확인한다.

경로 Inspector의 **좌표 확인 맵**은 제작 확인용이다. 각 경유지 버튼으로 Map Editor의 그 칸을 연다. 경로를 여러 맵의 배치에 공유하면 콘텐츠 검사는 모든 해당 맵의 범위·이동 가능 타일을 확인한다.

경유지 진행은 안정 ID가 아닌 **숫자 인덱스**로 저장한다. 배포 뒤 같은 routeId의 경유지를 재정렬하거나 삭제하면 기존 저장 호환성을 보장하지 않는다. 번호가 범위 안에 남아도 다른 경유지를 가리킬 수 있어 정적 검사가 의미 변경을 탐지하지 못한다. 새 경로 ID를 발급해도 이전 ID를 제거하면 기존 저장은 로드를 거부하므로, 배포된 경로 변경은 별도 저장 마이그레이션 정책과 함께 진행한다.

## 2. 맵에 배치하기

Map Editor의 이벤트 배치에서 **NPC 프로필 (선택)**을 연결한다. 일괄 배치할 때는 **선택적 NPC 프로필** 브러시도 지정한다.

대사·격파 상태는 기존 EventDefinition으로 작성하고 이동·일과·외형은 NpcDefinition으로 지정한다. NPC 프로필이 없는 기존 오브젝트는 그대로 정적인 이벤트다. 일반 NPC는 이벤트 정의 없이 이동 프로필만 둘 수도 있다. 보이는 적은 PlayerTouch 이벤트 정의를 연결한다.

플레이어를 막는 일반 NPC의 점유는 NpcDefinition.blocksMovement와 현재 이벤트 페이지의 blocksMovement를 함께 적용한다. 이벤트 정의가 있는 배치는 두 값이 모두 참일 때 플레이어를 막는다. 이벤트 정의가 없으면 NPC 프로필 값으로 판단한다. 완전히 비차단 NPC를 만들려면 프로필과 해당 페이지를 모두 비차단으로 설정해 두면 된다. NPC끼리는 현재 칸과 목적지 예약을 충돌 검사에 사용한다.

NPC의 저장 문맥은 **mapId + placement.id**다. 같은 NPC 정의를 두 배치가 공유해도 위치·방향·경로 진행과 셀프 스위치는 배치별로 관리한다. 배치 복제·영역 붙여넣기·맵 복제는 NPC 참조를 보존하고 복사본에 새 배치/맵 ID를 발급한다.

이동은 XZ 격자의 이동 가능 타일과 현재 오브젝트·NPC·플레이어 점유를 확인한다. 자신의 점유 칸을 장애물로 취급하지 않고 목적지 예약으로 동시에 같은 칸에 들어가지 않게 한다. 막히면 정해진 재시도 횟수·간격 안에서 기다리거나 경로를 다시 찾으며, 계속 실패한 명시적 이동은 실패 결과를 반환한다.

maxBlockedRetries, retryInterval, pathNodeBudget는 무한 대기·탐색을 제한하는 제작 설정이다. 좁은 통로에 두 NPC와 플레이어를 배치했을 때 우회로가 있는지 실제 Play로 확인한다. 정적 검사는 모든 시간의 동적 도달 가능성을 보장하지 않는다.

## 3. 날짜·시간 일과

schedules는 마지막으로 일치하는 항목이 우선한다. 각 항목은 다음을 지정한다.

- firstDay와 lastDay: 적용할 시작/끝 날짜. lastDay=0은 끝 날짜 제한 없음.
- startMinute와 endMinute: 하루의 분 단위 시각. 예를 들어 08:00=480, 12:00=720이다. 시작은 포함하고 종료는 제외한다.
- conditions: 기존 스위치·변수·셀프 스위치·날짜 등 상태 조건.
- route 또는 stationCell/yaw: 이동 경로 또는 정지 칸과 방향.

시작이 종료보다 크면 자정을 넘는 구간이다. 자정 뒤 구간은 전날부터 시작한 일과의 날짜에 속한다. 시작과 종료가 같은 구간은 잘못된 설정이다. 아무 일과도 일치하지 않으면 기본 경로/배치 기준을 사용한다.

AdvanceTime으로 시간이 크게 바뀌면 지나간 분마다 모든 움직임을 재생하지 않고 현재 일과를 재평가한다. 영구 위치/방향 override가 있으면 일과보다 우선하며 ResumeNpc로 자동 동작을 다시 허용한다.

일과의 시작 칸이 점유되어 있으면 현재 위치와 이전 경로/일과 체크포인트를 유지하며 정해진 횟수만 재시도한다. 재시도 소진은 Blocked 진단으로 표시한다. 실패한 이동을 일과 완료로 저장하지 않으며, 재시도 횟수 자체는 저장하지 않는다. 로드나 맵 재진입 때 현재 조건과 점유로 다시 평가하므로 막힘이 해소되면 일과 배치가 성공할 수 있다.

대사·선택·전투·메뉴 같은 모달과 디버거 정지 중에는 일반 NPC의 배경 이동을 멈춘다. 명시적 전경 이동 명령은 해당 이벤트의 소유권 아래 실행한다.

## 4. 이벤트에서 움직이기

Event Editor에 다음 명령을 추가한다. key에는 **현재 맵의 배치 ID**를 사용한다. 비우면 명령을 호출한 NPC 배치 문맥을 사용한다. npcId는 정의 ID이므로 이동 대상 키로 쓰지 않는다.

| 명령 | 설정 |
| --- | --- |
| MoveNpc | key, 목적지 cell, 영구 override boolValue |
| FaceNpc | key, 방향 각도 intValue, 영구 override boolValue |
| StopNpc | key, 영구 override boolValue |
| ResumeNpc | key. 자동 경로·일과를 재개 |

MoveNpc·StopNpc·FaceNpc는 안전한 셀 경계를 사용한다. 결과는 Succeeded, Blocked, Invalid, Cancelled, Busy로 구분하며 성공하지 않은 명령은 이벤트 실패를 보고하고 후속 명령을 진행하지 않는다. 맵 이탈·로드·취소 후 이전 이동 작업이 새 세션의 NPC를 바꾸지 않게 한다.

이 명령은 전경 이벤트에서 사용한다. Parallel 및 배경에서 호출되는 공통 이벤트에 직접 넣으면 배경 허용 검사에서 거부한다. 배경에서 연출이 필요하면 기존 RequestForeground를 사용한다.

FaceNpc의 영구 플래그를 끄면 현재 칸 이동을 마치고 방향을 바꾼 뒤 이전 자동 이동 여부를 유지한다. StopNpc의 임시 정지는 현재 세션에서만 유지하며 저장·로드 뒤에는 경로/일과를 재평가한다. 영구 정지를 원하면 boolValue를 켠다. ResumeNpc는 영구 override를 해제하고 현재 일과로 복귀한다. 디버거에서 한 단계 실행하면 해당 전경 NPC 명령이 끝날 때까지 그 명령의 NPC만 움직이고 다음 명령과 배경 NPC는 정지한다.

기존 명령 데이터의 boolValue 기본값은 true다. 새 이동/방향/정지 명령을 임시 연출로 쓸 때는 영구 플래그를 명시적으로 끈다. 기본 경로가 없는 적을 포함하여 영구 override가 없는 정지 일과의 위치가 정지점과 다르면 로드 때 현재 일과의 정지점을 재평가한다. 숨김/비차단 격파 페이지의 위치 기록은 유지한다.

## 5. 보이는 적

NpcDefinition에 enemy를 연결하고 순찰 경로와 감지 설정을 지정한다. approachPlayer, detectionRadius, leashRadius, contactRadius, requireLineOfSight로 접근 범위를 정한다. 반경은 셀 단위다. 플레이어가 감지 범위와 시야 안에 있을 때 접근하고 추적 범위를 벗어나면 순찰 동작으로 돌아간다.

배치의 이벤트 페이지는 **PlayerTouch → StartEncounter**를 사용한다. 승리 시 기록하는 defeated 셀프 스위치에 맞는 뒤쪽 페이지를 보이지 않고 비차단 상태로 작성하면 격파된 적의 접근·접촉을 멈춘다. 이탈·패배·취소는 기존 전투 결과 규칙을 유지한다.

NPC Lab의 전투는 맵에서 보이는 적의 접근·접촉으로 시작한다. 기존 이벤트의 전투 명령도 계속 사용할 수 있다.

## 6. 저장과 검사

저장 v4는 기존 v1~v3를 읽으며 이전 저장의 NPC 기록은 빈 목록에서 시작한다. 기존 아이템·이벤트 완료·거래·병렬 체크포인트와 생존/여정 상태는 유지한다.

NPC별 맵/배치/정의 ID, 완료된 셀, 방향, 경로 ID·진행 번호, 일과 ID·평가 시각과 영구 override를 저장한다. 탐색 경로·목적지 예약·보간·대사 객체·Coroutine은 파일에 넣지 않는다. 복원 후 필요한 탐색/표현을 다시 만든다.

이동 중 저장을 요청하면 Pending으로 접수하고 새 이동을 시작하지 않은 채 진행 중인 한 칸을 마친 뒤 기록한다. 대기 중에는 플레이어 입력과 게임 시간 진행을 막으며 UI와 Event Debugger에서 상태를 확인할 수 있다. GameSession.Save의 참 반환은 요청 접수도 포함하므로 파일 기록 완료는 SaveStatus의 Completed 또는 SaveCompleted 통지로 확인한다. 기록 실패는 Failed, 맵 변경·새 게임 등으로 취소되면 Cancelled다.

제거된 맵·NPC·경로·일과, 범위 밖/이동 불가 셀, 잘못된 진행 번호 등 해석할 수 없는 기록은 로드를 취소한다. 읽은 후보를 먼저 검증하고 성공한 뒤 세션에 적용한다. 원본 v1~v3 파일은 읽기만 하며 다음 명시적 저장에서 v4를 기록한다.

플레이어의 저장 칸이 현재 지형에서 이동 불가하면 기존 정책에 따라 거부한다. 유효 지형에서 NPC/고정 이벤트와 겹친 플레이어는 가장 가까운 유효 셀로 복구하며 같은 거리면 행 우선으로 선택한다. NPC끼리의 충돌은 임의 이동으로 해결하지 않고 거부한다.

사전 검증 실패는 실행 중 이벤트·NPC 보간·예약 저장·전경 큐를 유지한다. 맵 생성 또는 StateReplaced 외부 구독자에서 예기치 않은 예외가 나면 이전 상태/맵/플레이어와 NPC 보간·예약·큐·디버거 정지를 복구한다. 이 과정에서 재생성된 배경 이벤트는 지속 체크포인트부터 다시 시작하며 임의 Coroutine 중첩 스택을 되살리지는 않는다. 반복 가능 보상은 기존 GrantOnce 계약을 사용한다.

**No Sleep > Validate Content**는 안정 ID 중복, 잘못된 수치/일과, 모든 배치 맵의 경유지·정지점·시작점과 적의 접촉 이벤트 정의를 검사한다. Content Browser는 NPC/경로 카탈로그와 사용 위치·진단을 표시하고 해당 에셋으로 이동한다. Play 중 제작 에셋 편집은 잠그며 실행 진단은 NPC 서비스 상태 및 Event Debugger에서 확인한다.

## 7. NPC 실험 씬

**No Sleep > Create NPC Lab**을 실행하면 Assets/NoSleep/Scenes/NoSleepNpcLab.unity와 Data/NpcLab 아래 데이터를 만든다. 기존 씬/에셋이 있으면 열고 검사하며 사용자 데이터를 덮어쓰지 않는다. 두 맵을 Bootstrap에 연결하고 빌드 목록에 추가한다.

1. 새 게임을 시작하고 교차 담당 A/B의 반대 방향 이동을 관찰한다. 가운데 보관함이나 플레이어 점유를 피하거나 기다리는지 확인한다.
2. 각 담당자에게 말을 건다. 같은 공통 인사를 사용해도 greeted 셀프 스위치는 독립이며 대사 동안 이동이 멈춘다.
3. 시간과 이동 장치에서 **네 시간을 보낸다**를 선택한다. 초기 08:00에서 정오가 되어 시간표 담당자가 정지점 (13,10)으로 일과를 바꾼다.
4. 장치에서 A를 멈추고 저장한다. 이 샘플의 StopNpc는 boolValue=true로 영구 정지를 기록한다. 저장 완료 표시를 확인하고 불러온 뒤 A가 계속 정지하는지 확인한다. **재개한다**를 선택하면 override를 해제한다.
5. 뒤쪽 연습용 그림자에 접근해 순찰·접근·전투를 확인한다. 승리하고 맵을 왕복하거나 로드한 뒤 다시 나타나지 않는지 확인한다.
6. 옆 작업실로 이동하고 돌아온다. 담당자들의 위치와 배치별 인사·격파 상태를 확인한다.
7. 막힌 칸의 명시적 이동, 취소·로드 실패도 별도 제작 데이터/테스트로 확인한다. 자동 검증과 사람이 화면에서 확인한 결과는 구분하여 기록한다.

이 씬은 NPC 기능을 검증하는 별도 샘플이다. 피로 누적을 0으로 두며 본편 이동 속도·전투 밸런스·동료의 행방·정식 시나리오를 확정하지 않는다. 장거리 NPC 맵 이동, 애니메이션·대사 연출·음향은 후속 단계다.
